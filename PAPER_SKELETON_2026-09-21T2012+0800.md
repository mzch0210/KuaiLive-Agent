# 2. Core thesis

> **Explicit relationship memory has no fixed global ordering relative to a strong identity-aware sequential recommender. Its marginal ranking utility varies across user states, candidate universes, and temporal regimes. Under sampled-active LOO it is globally inferior yet locally complementary; under full-active ranking and strict temporal shift it becomes broadly valuable. Learning conditional relative utility enables selective memory escalation that exploits this heterogeneity beyond generic hard-case routing.**

The scientific object is therefore the **distribution of memory-relative utility across states and regimes**, not a universal claim that Memory is globally stronger or globally weaker.

---

# 3. Novelty boundary

The paper does **not** claim invention of generic instance-wise expert routing. Learning-to-Defer already studies routing among predictors/experts, including fixed-expert/two-stage settings and accuracy–cost trade-offs. The recommendation literature also contains adaptive-computation and uncertainty-guided routing.

The defensible contribution is the following combination in live-stream recommendation:

1. an interpretable **explicit relationship-memory specialist** separate from the base recommender;
2. a strong room+streamer **identity-aware sequential base** before making any memory claim;
3. direct estimation of **specialist-minus-base offline ranking utility**, not merely generic base difficulty;
4. a sampled-active regime in which Memory is globally inferior yet locally complementary;
5. evidence that aggregate Memory-vs-Base ordering reverses under full-active candidate ranking and strict temporal shift;
6. matched-budget evidence that relative-utility routing outperforms generic difficulty routing;
7. serving evidence that selector complexity and specialist invocation jointly determine cost.

Avoid all “first” claims. Position Learning-to-Defer as generic methodological lineage, DS-Frame/GUIDER as recommendation-specific routing neighbors, and MemRec as a memory/agentic neighbor.

# 4. Primary task and formulation

The main task is **next-live-room recommendation**. Earlier streamer-only SASRec experiments become supporting/appendix evidence rather than the manuscript spine.

Let `B` denote the strong Dual-ID room+streamer sequential base, `M` the explicit relationship-memory specialist, and `u_K(A,x)` the event-level offline ranking utility of method `A` on state `x` (primary instance: NDCG@10).

Realized relative memory utility:

\[
\Delta_m(x)=u_K(M,x)-u_K(B,x).
\]

Conditional expected relative utility:

\[
\eta(z,r)=\mathbb E[\Delta_m(X)\mid Z=z,R=r],
\]

where `z=(s_x,c_B(x))` combines interaction/user state and base-confidence information, while `r` denotes an evaluation/serving regime such as candidate universe or temporal regime.

Within a frozen regime, fit on development data only:

\[
\hat\eta(z)=g(z),
\]

and escalate to Memory when

\[
\hat\eta(z)>\tau.
\]

`utility` always means **offline predictive ranking utility**. It is not GMV, conversion, satisfaction, welfare, or a causal treatment effect.

# 5. Research questions

## RQ1 — Does explicit relationship memory have a fixed global advantage over a strong identity-aware sequential recommender?

**No.** The aggregate ordering changes by regime: Memory < Dual-ID under sampled-active LOO, but Memory > Dual-ID under full-active LOO and strict temporal GTS.

## RQ2 — Can memory-relative utility be predicted beyond persistent identity and generic base difficulty?

**Yes.** Selective gain survives a streamer-heavy Dual-ID identity control. In sampled-active and full-active regimes, same-feature relative-utility routing significantly outperforms generic base-difficulty routing at the same specialist budget.

## RQ3 — How do candidate universe and temporal regime change memory utility and escalation behavior?

Candidate expansion from 575 sampled-active candidates to all legally active rooms reverses the aggregate Memory−Base sign and increases native escalation from about 14% to 64%. Strict temporal shift also makes Memory broadly valuable with approximately 60–75% escalation.

## RQ4 — What is the effectiveness–invocation–latency trade-off of selective memory?

Selector cost itself can dominate incremental latency, so invocation rate alone is not a valid compute proxy.

# 6. Four contributions

## C1 — Regime-dependent relationship-memory utility

| Regime | Base NDCG@10 | Always Memory | Memory − Base | Selective | Invocation |
|---|---:|---:|---:|---:|---:|
| Sampled-active LOO (575) | 0.607844 | 0.565887 | **−0.041956** | **0.621018** | 14.25% |
| Full-active LOO (~8.3k candidates) | 0.398353 | 0.432019 | **+0.033666** | **0.451801** | 64.44% |
| GTS-Last | 0.496155 | 0.573694 | **+0.077538** | 0.568972 | 59.80% |
| GTS-Successive | 0.403007 | 0.503678 | **+0.100671** | 0.500434 | 74.73% |

Primary interpretation: **the prevalence and aggregate sign of memory-relative utility are regime-dependent.** Do not compare absolute NDCG values across candidate universes as though task difficulty were identical.

## C2 — Relative-utility routing contains information beyond generic difficulty

Sampled-active, exact `K=1457`:

- difficulty-router gain vs Dual-ID: **+0.007716**;
- relative-utility-router gain: **+0.013174**;
- Utility − Difficulty: **+0.005458**, 95% CI **[+0.002659,+0.008464]**;
- predicted-vs-realized utility Spearman `rho=0.2049`;
- learned router captures ~**17.0%** of exact-K oracle gain.

Full-active, exact `K=6587`:

- difficulty-router gain: **+0.039017**;
- relative-utility-router gain: **+0.053448**;
- Utility − Difficulty: **+0.014431**, 95% CI **[+0.010938,+0.017908]**;
- Spearman `rho=0.2399`;
- learned router captures ~**50.3%** of exact-K oracle gain.

Use **“modestly predictive but decision-useful utility stratification”**, not “well calibrated” or “near oracle.”

## C3 — Identity control, candidate-universe validity, and temporal robustness

Sampled-active identity control:

- Room SASRec: 0.315093;
- Streamer SASRec: 0.600308;
- Dual-ID: **0.607844**;
- Memory: **0.565887**;
- Selective: **0.621018**;
- Selective − Dual-ID: **+0.013174** with positive bootstrap CI;
- dev alpha: room 0.1 / streamer 0.9.

Full-active test contains all legally active rooms at each target timestamp: mean 8,269 candidates, median 8,132, p95 12,301. Two pre-specified protocols both pass:

- strict-transfer Selective − Base: **+0.031799**, CI **[+0.028143,+0.035554]**, invocation 29.18%;
- full-active-native Selective − Base: **+0.053448**, CI **[+0.048252,+0.058836]**, invocation 64.44%;
- native Selective also exceeds Always Memory by ~0.01978.

Strict temporal validation shows Memory becomes broadly useful; Selective preserves most full-memory gain but does not always beat Always Memory. This is a regime-prevalence result, not a universal selective-accuracy dominance claim.

## C4 — Selector complexity is part of selective-inference cost

| Gate | NDCG@10 | Delta vs Dual-ID | Invocation | Mean E2E latency |
|---|---:|---:|---:|---:|
| HGB | 0.621018 | +0.013174 | 14.25% | 2.0066 ms |
| Ridge | **0.623876** | **+0.016032** | 30.99% | **1.3872 ms** |
| tiny MLP | 0.617076 | +0.009232 | **10.37%** | **1.2720 ms** |

Selector-only means are ~0.617 ms (HGB), 0.00242 ms (Ridge), and 0.00575 ms (tiny MLP). HGB remains the frozen scientific selector; Ridge is a deployment variant.

# 8. Narrative logic

1. **Setting:** live-room recommendation combines ephemeral rooms with persistent streamer relationships.
2. **Strong-base requirement:** room-only modeling is weak, so construct streamer-heavy Dual-ID before making memory claims.
3. **Sampled-regime paradox:** Always Memory is worse than Dual-ID, yet selective Memory improves it.
4. **Mechanism:** relative-utility scores stratify realized Memory−Base advantage; matched-budget utility routing beats difficulty routing.
5. **Candidate-regime reversal:** full-active evaluation reverses aggregate Memory−Base ordering while native selective routing beats both fixed choices.
6. **Temporal-regime shift:** Memory becomes broadly valuable and escalation rises toward 60–75%.
7. **General lesson:** model ranking is not fixed; the distribution of relative specialist utility changes across recommendation regimes.
8. **Systems lesson:** selector complexity plus specialist invocation, not invocation alone, determines serving cost.

# 12. Claim guardrails

Do not claim:

- Memory is globally inferior in all regimes;
- Memory is globally superior in all regimes;
- generic deferral/routing is novel;
- utility estimates are well calibrated;
- the HGB selector is close to oracle;
- Selective always beats Always Memory under temporal shift;
- Selective routing is universally superior to DS-Frame;
- current MemoryFusion is an LLM/agentic recommender;
- causal GMV/conversion/satisfaction lift;
- official DCGLive scores are directly comparable under our frozen protocol.

Preferred overarching sentence:

> **Relationship memory is a regime-dependent specialist: its aggregate value can change sign across candidate and temporal regimes, while conditional relative-utility estimation consistently reveals exploitable within-regime heterogeneity beyond fixed model choice and generic hard-case routing.**
