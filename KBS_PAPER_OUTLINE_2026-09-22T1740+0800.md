The journal also states that it seeks a balance of theory and practical study and encourages new intelligent models, methods, systems, and software tools. For this manuscript, the strongest KBS positioning is therefore **not** “a new live-streaming recommender” and **not** “an agent memory application.” The paper should be presented as a knowledge-specialist decision framework that asks when an explicit relationship-knowledge source has positive incremental utility beyond a strong sequential model.

Key KBS framing:

> **Relationship memory is a regime-dependent specialist. The methodological problem is to estimate its conditional specialist-minus-base utility and invoke it only when its incremental knowledge is expected to improve ranking.**

# 3. One-sentence thesis

> **Explicit relationship memory is not globally superior to a strong sequential recommender; its marginal predictive value is regime-dependent, peaks when persistent relationships fall outside the base model’s finite context, and can be exploited by learning specialist-minus-base utility rather than generic case difficulty.**

---

# 4. Four main contributions

## Contribution 1 — Problem and estimand

Reformulate memory augmentation from a fixed model-comparison problem into a **conditional specialist-utility** problem.

Let `B` be the strong sequential base, `M` the relationship-memory specialist, and `u_K(A,x)` an event-level ranking utility:

\[
\Delta_m(x)=u_K(M,x)-u_K(B,x).
\]

For observable state `Z=z` and recommendation regime `R=r`:

\[
\eta(z,r)=\mathbb E[\Delta_m(X)\mid Z=z,R=r].
\]

The practical question is not “is Memory better?” but:

\[
\eta(z,r)>0\ ?
\]

## Contribution 2 — Selective specialist framework

Estimate `\hat\eta(z)` from user/state and base-confidence features and invoke Memory only when its estimated incremental utility is positive enough. Compare directly against:

- Always Base;
- Always Memory;
- same-budget generic Difficulty routing;
- exact-budget Oracle headroom.

This isolates **memory-solvability** from generic uncertainty/difficulty.

## Contribution 3 — Mechanism: relationship horizon

Show that Memory utility changes sign across three diagnostic regimes:

- `recent-visible`: relationship already inside the base context → Memory redundant/harmful;
- `long-horizon-only`: relationship exists but lies outside the finite context → Memory strongly beneficial;
- `unseen`: no recoverable relationship → Memory strongly harmful.

This mechanism is more informative than repeat/novel labels.

## Contribution 4 — Multi-regime and held-out validation

Demonstrate the principle across:

- KuaiLive candidate-universe shifts;
- KuaiLive temporal shifts;
- a strong LiveRec/Twitch sequential base;
- a frozen, one-shot untouched Twitch test.

The external test reproduces both selective effectiveness and the relationship-horizon mechanism without test tuning.

# 5. Light decision-theoretic motivation

KBS benefits from a compact formal decision view rather than presenting routing as a heuristic.

If specialist invocation has additional cost `c(x)` and cost weight `lambda`, choose Memory when:

\[
\mathbb E[\Delta_m(X)\mid Z=z]
>
\lambda\,\mathbb E[c(X)\mid Z=z].
\]

With negligible or fixed specialist cost, this reduces to:

\[
\mathbb E[\Delta_m(X)\mid Z=z]>0.
\]

This is a **formal motivation**, not a claim of a new general decision-theory result. It connects naturally to the measured selector/invocation/latency trade-off.

## 8. Main Results III — Relationship horizon explains when Memory helps

### Twitch DEV → untouched TEST replication

| Horizon | DEV Memory−Base | TEST Memory−Base |
|---|---:|---:|
| recent-visible | −0.01995 | **−0.01935** |
| long-horizon-only | **+0.23097** | **+0.22045** |
| unseen | −0.19562 | **−0.18215** |

Untouched test CIs:

- recent-visible: −0.01935 [−0.02234,−0.01633]
- long-horizon-only: **+0.22045 [+0.21140,+0.23001]**
- unseen: −0.18215 [−0.18681,−0.17715]

Mechanism sentence:

> **The strongest complementary value of explicit relationship memory arises when a persistent relationship is known from older history but is absent from the sequential model’s finite visible context.**

### Why repeat/novel is insufficient

Test:

- repeat Memory−Base = −0.01475
- novel Memory−Base = −0.07392

The nominal novel group mixes strongly positive long-horizon-only events with strongly negative unseen events.

### Utility vs Difficulty selection composition

Utility allocates substantially more budget to long-horizon-only cases and much less to unseen cases than Difficulty. This provides a direct mechanism for Utility > Difficulty.

## 9. Main Results IV — Utility estimation identifies a useful positive tail

Twitch test predicted vs realized utility Spearman is only **0.173**, so do not claim strong pointwise calibration.

Frozen utility strata transfer coherently:

- D1–D8: negative realized utility;
- D9: approximately neutral (−0.0014);
- D10: **+0.0724** realized versus ≈ +0.080 predicted.

The scientific claim is **coarse utility ranking / positive-tail identification**, not accurate event-level regression.

## 12. Discussion

### 12.1 What “knowledge” means here

Relationship Memory is an explicit structured source of persistent user–creator knowledge separate from the latent sequential state.

### 12.2 Why Memory can hurt

Redundancy in recent-visible cases and absent evidence in unseen cases create negative marginal utility even when the same specialist is highly useful in long-horizon-only cases.

### 12.3 Why Difficulty fails

Difficulty answers “where is Base weak?”; utility answers “where does this specific specialist contain complementary information?” These are different questions.

### 12.4 Remaining headroom

Twitch test Utility captures only **11.71%** of exact-budget Oracle gain. This is evidence for real but still imperfect utility estimation.

### 12.5 Limits

- two live-stream platforms;
- offline predictive utility only;
- no causal GMV/conversion claim;
- relationship horizon is diagnostic, not an online feature;
- current Memory specialist is transparent and non-LLM;
- modest event-level utility correlation;
- P1.3 is frozen and cannot be reused for model selection.

## 13. Conclusion

Conclude with the methodological shift:

> **The relevant question is not whether relationship memory is globally stronger than a sequential recommender, but when its incremental knowledge is positive and sufficiently valuable to justify escalation.**
