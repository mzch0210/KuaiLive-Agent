\section{Introduction}

Sequential recommender systems infer users' evolving preferences from ordered interaction histories, and self-attentive models such as SASRec and BERT4Rec established strong sequence encoders for next-item recommendation \cite{kang2018sasrec,sun2019bert4rec}. Yet stronger sequence modeling does not remove a more basic question: when does an additional source of historical evidence still contain information that is incremental relative to what the base recommender already represents? More evidence is not necessarily more useful. An auxiliary source can be redundant when the base already represents overlapping information, ineffective when no target-specific evidence exists, or complementary when it retains useful information outside the base's current representation. The relevant problem is therefore not whether more historical evidence can improve recommendation in general, but whether that evidence has positive marginal value relative to what the base already captures.

Recent recommendation research has developed increasingly sophisticated mechanisms for integrating heterogeneous evidence, including adaptive gating across collaborative, semantic, structural, and long-/short-term preference signals and information-theoretic fusion that explicitly seeks complementary multimodal cues while reducing redundancy \cite{xie2026mhgfcl,zhu2026mifusr}. These advances primarily address how available evidence should be represented, weighted, aligned, or fused. This leaves a different methodological question: does a particular auxiliary evidence source contribute positive marginal value beyond a strong base recommender for the current recommendation event? We refer to this perspective as \emph{Base-relative evidence valuation}. The unit of analysis is not the standalone quality of an auxiliary model, but the incremental utility of its evidence conditional on what the base already represents.

Live-streaming recommendation provides a useful setting in which to study this question because candidate availability changes over time and repeat consumption of specific channels is substantial \cite{rappaz2021liverec}. KuaiLive further provides a real-time interactive benchmark with live-room timing information and multiple forms of user--streamer interaction, enabling evaluation under dynamic live-streaming conditions \cite{qu2026kuailive}. We therefore use a relationship-memory specialist as a transparent source of persistent user--creator evidence. For a target creator, this evidence can occupy three Base-relative analysis states: \emph{represented}, when the target relationship appears in the base-visible sequence; \emph{recoverable but unrepresented}, when it exists only in older history; or \emph{unavailable}, when no previous target-specific relationship exists. These states describe how the specialist's evidence relates to the current base representation; they are used only for mechanism analysis and are not available to the online selector.

Our empirical results show why this distinction matters. On KuaiLive, the aggregate ordering between the relationship-memory specialist and a strong base recommender reverses across candidate regimes even when the underlying user--time--target instances and evidence-state composition are held fixed across candidate-set constructions, indicating that regime dependence cannot be reduced to state prevalence alone. On Twitch/LiveRec, development-set analysis reveals strong conditional heterogeneity across the three evidence states, and the same sign structure reproduces on untouched held-out test data. A development-only context-capacity comparison offers convergent evidence: among matched target instances whose relationship becomes visible at a larger context length, specialist-minus-base utility contracts by approximately 0.42--0.45 NDCG@10 while the relationship-memory specialist is held fixed. Because the base recommender is also retrained at each context length, the contraction cannot be attributed to visibility alone; it is consistent with the visibility account alongside changes in base representation quality.

This heterogeneity motivates selective specialist use. We treat the event-level ranking-utility difference between the relationship-memory specialist and the base recommender as the decision quantity to be predicted, rather than relying only on where the base is weak. The distinction is substantive: base difficulty identifies hard events, whereas conditional relative utility aims to identify events for which this specialist is expected to improve upon the base. A difficult event may still contain no target-specific evidence recoverable by the relationship-memory specialist. In matched-budget analysis, utility-based selection concentrates more strongly on recoverable-but-unrepresented events, whereas a generic difficulty control disproportionately selects unavailable events. Post-hoc deferral and modern Learning-to-Defer already establish how routing rules can be learned on top of fixed predictors under accuracy--cost trade-offs \cite{narasimhan2022posthoc,mao2025mastering}. Our contribution is therefore not a new general deferral or gating formulation, but the characterization and operational use of the structured conditional utility of a transparent relationship-evidence specialist in recommendation.

The contributions of this work are threefold:
\begin{itemize}
    \item \textbf{Base-relative evidence valuation.} We operationalize the Base-relative value of persistent relationship evidence through the event-level marginal ranking utility of a transparent relationship-memory specialist relative to a strong base recommender, rather than through standalone specialist performance or generic base difficulty.
    \item \textbf{Relationship-evidence mechanism.} We characterize represented, recoverable-but-unrepresented, and unavailable evidence states, combine development-set evidence-state analysis with untouched held-out test replication and context-capacity comparisons across retrained base models, and show that evidence state structures---but does not deterministically fix---specialist utility across recommendation regimes.
    \item \textbf{Conditional decision and validation.} We connect specialist-relative utility to selective invocation and evaluate the resulting decision principle across KuaiLive regimes, strong-base controls, independent training seeds, and an untouched second-platform held-out test.
\end{itemize}
Although we instantiate the formulation with relationship memory in live-stream recommendation, the decision formulation applies to fixed auxiliary specialists more generally; the empirical claims of this study remain limited to the evaluated live-streaming platforms, candidate protocols, and ranking outcomes.

\section{Related Work}

\subsection{Sequential and Long-Horizon Recommendation}

Sequential recommendation models evolving user preference from ordered interaction histories. Self-attentive architectures such as SASRec and BERT4Rec established strong Transformer-style baselines by learning dependencies within historical sequences \cite{kang2018sasrec,sun2019bert4rec}. More recent work has strengthened user-intent representations through multi-level augmentation and contrastive learning \cite{ni2025idmarec}, while multi-interest and multi-granular models capture diverse structure within historical interactions \cite{sheng2025dsmgrec}. Such developments enrich historical representation beyond the original self-attentive baselines. This literature establishes that broader history can improve recommendation quality. The present study assumes a strong sequential base and asks a different question: whether a separately maintained source of persistent relationship evidence retains positive marginal value after accounting for what the base already represents.

\subsection{Auxiliary Evidence Integration, Reliability, and Harmful Information}

A closely related research line studies how heterogeneous auxiliary evidence should be incorporated into recommendation. Recent KBS work illustrates several increasingly refined strategies. Xie et al. combine collaborative, semantic, and structural views through multi-head gating and explicitly distinguish users' long-term interests from short-term preferences \cite{xie2026mhgfcl}. Zhu et al. formulate multimodal sequential fusion through mutual information, seeking complementary cross-modal information while reducing redundancy and modality noise \cite{zhu2026mifusr}. Zhang et al. further address irrelevant and imbalanced multimodal content through collaborative denoising and modality balancing \cite{zhang2026mcd4sr}. Evidence-centric recommendation has also moved beyond fusion: KAPER explicitly selects preference-relevant graph-path evidence using temporal and structural weighting and incorporates the selected evidence into candidate re-ranking and explanation generation \cite{kim2026kaper}. These studies improve how auxiliary information is represented, filtered, selected, or used downstream.

A second group of methods focuses on the quality or reliability of auxiliary evidence. Huo et al. model content-level and interaction-level reliability in multimodal recommendation \cite{huo2026reliability}. Related information-theoretic and knowledge-aware methods likewise distinguish informative signals from noisy or redundant ones. Reliability is therefore a natural conceptual neighbor of the present problem, but it is not equivalent to Base-relative marginal value: a signal may be reliable yet add little when the base already represents overlapping information.

Conditional evidence use has also been studied outside recommendation. Yerragunta et al. propose dynamic conditional gating for question answering over incomplete knowledge bases, controlling how structured KB evidence and textual evidence are aggregated \cite{yerragunta2026gating}. Negative-transfer research provides a complementary warning against assuming that additional information is uniformly beneficial; Peng et al. show that multimodal pretraining can harm downstream sequential recommendation and develop a re-learning strategy to mitigate that effect \cite{peng2025negative}. These studies motivate conditional treatment of auxiliary information without implying the same mechanism as the one studied here.

A broader decision-theoretic connection is the value of information (VOI), which quantifies the benefit that additional information can provide to a decision, often through expected utility improvement \cite{abbas2025voi}. Our setting differs from classical information acquisition: the auxiliary source is not an unobserved feature whose revelation must be purchased before acting, but a fixed relationship-memory specialist whose ranking contribution is evaluated relative to an already trained base recommender.

Collectively, these lines of work address the representation, reliability, selection, conditional integration, or potential harm of auxiliary information. The present work takes event-level marginal ranking utility relative to a trained base recommender as the primary object of analysis; in this sense, Base-relative evidence valuation complements rather than replaces evidence-integration or evidence-selection methods.

\subsection{Expert Routing, Selective Prediction, and Learning-to-Defer}

Selective prediction and Learning-to-Defer (L2D) provide the closest general decision-theoretic background. Mozannar and Sontag formulate L2D as jointly learning a predictor and a rejector that can defer decisions to an expert, with consistency results through cost-sensitive learning \cite{mozannar2020defer}. Narasimhan et al. study post-hoc deferral on top of a pretrained base model and optimize an accuracy--cost trade-off relative to an expert \cite{narasimhan2022posthoc}. Mao et al. develop stronger theoretical guarantees for single- and multiple-expert routing in both one-stage and two-stage settings \cite{mao2025mastering}, and recent work extends L2D to dynamically varying expert pools \cite{montreuil2026online}. Selective invocation of an expert, including on top of a fixed predictor, is therefore an established decision problem.

Recommendation also contains expert-style architectures. CeDRec, for example, uses adaptive in-context experts as components of a sequential representation \cite{sun2025cedrec}. Such systems adapt how representational experts contribute within the model, whereas the relationship-memory specialist studied here is maintained as a separate, transparent evidence source. The primary object of analysis is its specialist-minus-base ranking utility and the evidence conditions under which that utility changes. Accordingly, the generic difficulty control in our experiments serves a narrower mechanistic purpose: it tests whether base weakness alone is sufficient to identify cases where the relationship-memory specialist helps, rather than standing in for the broader L2D literature.

\subsection{Live-Streaming and Repeat-Aware Recommendation}

Live-streaming recommendation introduces domain-specific dynamics that are absent from static-item settings: rooms become available and unavailable over time, viewers repeatedly return to channels, and interactions between viewers and streamers evolve during sessions. Zhang et al. model the two-sided dynamics of viewers and anchors through bi-directional prediction \cite{zhang2021bidirectional}. Rappaz et al. identify dynamic availability and repeat consumption as defining characteristics of live-stream recommendation and propose LiveRec to model them \cite{rappaz2021liverec}. Later work develops dynamic room representation and interaction-aware preference modeling \cite{gao2023driver,chen2024preference}, while hypergraph and graph-based approaches capture richer viewer--channel interactions and repeated behaviors \cite{yu2024hypergraph,zhu2025repeated}.

These studies establish that dynamic availability, repeated consumption, and viewer--streamer interactions are central to live recommendation. Live streaming is therefore not introduced here as a new source of repeat behavior, but as an empirical setting in which target-specific relationship evidence can be represented in the base-visible sequence, remain recoverable only from older history, or be unavailable while the candidate environment itself changes. KuaiLive and Twitch/LiveRec provide complementary environments for studying this Base-relative evidence value \cite{qu2026kuailive,rappaz2021liverec}.

\section{Problem Formulation}
\label{sec:problem}

We formalize Base-relative evidence valuation as an event-level ranking-utility problem. The formulation distinguishes the offline evaluation of a fixed relationship-memory specialist from the pre-outcome decision of whether to invoke it. This distinction is central to the paper: the realized marginal benefit of the specialist can be measured only after the relevant target is observed, whereas a serving policy must act using information available beforehand.

\subsection{Recommendation Setting and Event-Level Ranking Utility}
\label{sec:event-utility}

For user $u$ at recommendation time $t$, let the pre-outcome decision context under evaluation regime $r$ be $\xi_r=(u,t,\mathcal{C}^{(r)}_{u,t},\mathcal{H}_{u,t})$, where $\mathcal{C}^{(r)}_{u,t}$ is the candidate set under that regime and $\mathcal{H}_{u,t}$ is the interaction history available strictly before $t$. An evaluated event is $x_r=(\xi_r,y)$, where $y\in\mathcal{C}^{(r)}_{u,t}$ is the observed relevant target. The underlying interaction instance $(u,t,y,\mathcal{H}_{u,t})$ may be held fixed while different candidate-set constructions produce distinct decision contexts and, hence, distinct full events. Ranking models receive the context but not $y$, which is used only for offline evaluation. For concision, the subscript $r$ on $\xi$ and $x$ is omitted when a regime is fixed.

Let $A$ be a ranking model and let $r_A(y\mid\xi)$ denote the 1-indexed rank assigned to $y$ among $\mathcal{C}_{u,t}$. For cutoff $K$, define the event-level ranking utility
\begin{equation}
    u_K(A,x)=
    \begin{cases}
        \displaystyle \frac{1}{\log_2\!\left(r_A(y\mid\xi)+1\right)}, & r_A(y\mid\xi)\le K,\\[6pt]
        0, & r_A(y\mid\xi)>K.
    \end{cases}
    \label{eq:event-ndcg}
\end{equation}
With one relevant target per event, Eq.~\eqref{eq:event-ndcg} is the event-level contribution to NDCG@$K$; aggregate NDCG@$K$ is its empirical mean over evaluation events. Because rank utility is defined relative to the event-specific candidate set, changing candidate construction can change Base-relative specialist value even when the underlying user--target history is unchanged. The formulation below requires only a scalar event-level utility; NDCG@$K$ is used because it is the primary ranking metric in our evaluation.

\subsection{Base-Relative Specialist Utility}
\label{sec:relative-utility}

Let $B$ denote a fixed base recommender and $M$ a fixed relationship-memory specialist. For a given selective-decision experiment, both rank the same event-specific candidate set and are fixed before the invocation policy is learned. We define the specialist-minus-base utility
\begin{equation}
    \Delta_m(x)=u_K(M,x)-u_K(B,x).
    \label{eq:delta-memory}
\end{equation}
A positive value indicates an event-level ranking gain from using the specialist instead of the base, zero indicates no marginal gain, and a negative value indicates that replacing the base ranking with the specialist ranking is harmful for that event. Importantly, $\Delta_m(x)$ is an \emph{operational} marginal value of persistent relationship evidence as instantiated by the fixed specialist $M$ relative to the fixed base $B$. It should not be interpreted as an intrinsic or model-independent information value of the underlying history. Its magnitude can depend on the base, the specialist implementation, cutoff $K$, candidate environment, and operating regime.

The realized $\Delta_m(x)$ is an offline supervisory quantity because computing it requires the observed target $y$ and the rankings produced by both $B$ and $M$. Selective specialist use must therefore estimate its conditional expectation from information available before $y$ is known.

\subsection{Conditional Relative Utility}
\label{sec:conditional-utility}

Let $R$ index the operating recommendation condition under which candidate construction, temporal availability, or related protocol elements are fixed, and let $Z$ denote the information available at invocation time. We condition on $R=r$ to describe a regime-specific event distribution; $R$ need not be an explicit feature of $Z$. The variable $Z$ is constructed only from pre-outcome information, such as user and history summaries, candidate-set descriptors, and confidence signals produced by the base recommender. Define the conditional specialist-minus-base utility as
\begin{equation}
    \eta_r(z)
    =\mathbb{E}\!\left[\Delta_m(X)\mid Z=z,R=r\right].
    \label{eq:eta}
\end{equation}
When training and evaluating within a fixed regime, we suppress $r$ for notational simplicity. A learned estimator $\hat{\eta}_r(z)$ scores events by expected specialist-minus-base value; Section~4 specifies its implementation.

Let $a(Z)\in\{0,1\}$ denote a pre-outcome selection policy, where $a(Z)=0$ uses the base ranking and $a(Z)=1$ uses the specialist ranking. This includes development-frozen score-threshold policies but excludes any dependence on the realized target. For an evaluated event $x$, define $u_K^{\mathrm{sel}}(x;a)=(1-a)u_K(B,x)+a\,u_K(M,x)$. The expected improvement over always using the base satisfies
\begin{align}
    &\mathbb{E}\!\left[u_K^{\mathrm{sel}}(X;a)-u_K(B,X)\mid R=r\right] \\
    &\qquad=\mathbb{E}\!\left[a(Z)\Delta_m(X)\mid R=r\right]
    =\mathbb{E}\!\left[a(Z)\eta_r(Z)\mid R=r\right].
    \label{eq:expected-selective-gain}
\end{align}
Equation~\eqref{eq:expected-selective-gain} gives the decision rationale for estimating $\eta_r$: under a fixed regime, expected gain over the base is determined by which events are selected and their conditional relative utility.

The information boundary is strict. The observed target $y$, realized ranks, realized $\Delta_m(x)$, and the Base-relative evidence states used later for mechanism analysis are offline quantities and are excluded from $Z$. In particular, the represented, recoverable-but-unrepresented, and unavailable states are diagnostic variables rather than selector inputs. This formulation also distinguishes conditional relative utility from generic base difficulty: a difficulty score concerns the performance or uncertainty of $B$ alone, whereas $\eta_r(z)$ depends on the relative ranking utility of both $M$ and $B$. Base weakness therefore does not imply positive specialist-minus-base utility.

\subsection{Development-Frozen Selective Invocation and Matched-Budget Evaluation}
\label{sec:decision-rule}

The primary learned policy uses a score threshold determined without held-out test outcomes. Let $\hat{\eta}_r(z)$ be fitted on the development split, with out-of-fold predictions used to select a development-only threshold $\tau_r$. The policy is
\begin{equation}
    a_{\tau_r}(z)=\mathbf{1}\!\left[\hat{\eta}_r(z)>\tau_r\right],
    \label{eq:utility-threshold}
\end{equation}
where the model, feature transformations, and threshold are fixed before the held-out test is evaluated. The threshold is selected by development ranking utility, with a deterministic tie rule favoring fewer invocations. This pointwise policy makes no claim of enforcing an exact test-set invocation budget.

To compare selectors without confounding their invocation rates, a matched-budget analysis uses the number $m=\sum_{i=1}^{n}a_{\tau_r}(z_i)$ of invocations realized by the fixed utility policy on $n$ evaluation instances. The difficulty control then selects the $m$ largest predicted base-difficulty scores, with ties broken by stable instance index; the analysis-only Oracle selects the $m$ largest realized offline $\Delta_m(x_i)$ values. Both controls use the same $m$ as the learned utility policy. Thus, exact-budget Top-$m$ is an \emph{offline batch-comparison rule for controls}, not the serving rule of the primary utility policy or a method that assumes the future test batch is visible online. The realized Oracle upper bound is never available at decision time.

The ordering of predicted utility is sufficient to determine Top-$m$ selection for an offline equal-budget comparison. In contrast, the development-frozen threshold policy is sensitive to the absolute score scale and its transfer between splits. This distinction is particularly important when per-event utility is only imperfectly estimated.

A deployment system may additionally price the incremental cost of invoking the specialist. If $C_{\mathrm{inv}}\ge0$ denotes that cost and $\kappa_r(z)=\mathbb{E}[C_{\mathrm{inv}}\mid Z=z,R=r]$, the pointwise cost-sensitive benchmark is
\begin{equation}
    a_r^{*}(z)=\mathbf{1}\!\left[\eta_r(z)>\lambda\kappa_r(z)\right],
    \qquad \lambda\ge0.
    \label{eq:cost-rule}
\end{equation}
A deployable version replaces the unknown $\eta_r$ by $\hat{\eta}_r$ and would require a separately specified cost model and threshold. We do not claim to optimize such a calibrated cost model in the present experiments. The selection principles in this subsection follow established post-hoc expert-routing ideas rather than constituting a new deferral theorem.

\subsection{Regime-Level Utility Decomposition}
\label{sec:regime-decomposition}

To analyze why aggregate specialist value changes across operating conditions, let $S$ denote a mutually exclusive and exhaustive partition of Base-relative relationship-evidence states, instantiated operationally in Section~4 and used only for analysis. Writing $\bar{\Delta}_r=\mathbb{E}[\Delta_m(X)\mid R=r]$, the law of total expectation gives
\begin{equation}
    \bar{\Delta}_r
    =\sum_s P(S=s\mid R=r)
    \,\mathbb{E}\!\left[\Delta_m(X)\mid S=s,R=r\right].
    \label{eq:regime-decomposition}
\end{equation}
Equation~\eqref{eq:regime-decomposition} separates changes in evidence-state prevalence from changes in state-specific specialist utility. Both can vary across regimes. We use this identity as an analytical decomposition rather than as a causal model or a new theoretical result; $R$ characterizes the event distribution and need not be supplied as a selector feature.

Sections~4--6 instantiate these quantities, describe their leakage-safe estimation and analysis, and evaluate the resulting selective decisions across recommendation regimes.


\section{Base-Relative Evidence Valuation Framework}
\label{sec:framework}

We instantiate the operational comparison of Section~\ref{sec:problem} with a fixed sequential base recommender $B$, an independently scored relationship-memory specialist $M$, and a predictor of their conditional relative ranking utility. The three components serve distinct purposes: the base supplies the default candidate ranking, the specialist retains inspectable creator-level historical relationships, and the selector uses only information available before the outcome to decide whether the specialist's ranking should replace the base ranking. This separation allows the conditional value of the instantiated specialist to be studied without treating expert selection or long-/short-term aggregation as new architectures. Figure~\ref{fig:framework} distinguishes the pre-outcome selection path from offline supervision and mechanism diagnostics.

\subsection{Strong Sequential Base Recommenders}
\label{sec:framework-base}

The base $B$ is a trained ranking model evaluated only on the candidate set permitted by the current recommendation regime. For KuaiLive, we use an identity-aware dual-branch sequential base (Dual-ID), combining room-identity and streamer-identity sequence encoders. Room identity represents an individual live session, whereas streamer identity provides continuity across sessions. For each candidate set, the two branches produce separately standardized score vectors. Their linear combination uses development-selected room and streamer weights of $0.1$ and $0.9$, respectively; the resulting scores rank eligible live rooms. Thus, the streamer branch is not itself a change of the prediction target from rooms to creators. Candidate construction, within-candidate normalization, and the resulting base-confidence descriptors are regime dependent. Same-protocol comparisons with sequential alternatives serve to establish the credibility of the base rather than state-of-the-art superiority.

For Twitch/LiveRec, we retain the official availability-aware, repeat-aware LiveRec architecture \cite{rappaz2021liverec}. Its contextual and repeat-consumption components are both enabled, and the reference input contains at most $16$ preceding interactions. Eligibility follows the platform's time-dependent availability: a streamer is ranked only when available at the recommendation step. The two platforms therefore use different strong base instantiations, while the definition of $\Delta_m$ remains unchanged. Base checkpoints and development-selected settings are fixed within each specialist-selection experiment. Comparisons among context lengths use separately trained base checkpoints; they are not treated as a manipulation of input visibility alone.

\subsection{Transparent Relationship-Memory Specialist}
\label{sec:framework-memory}

The specialist $M$ scores eligible candidates from historical user--creator interactions available before the target time. Let $i$ denote a candidate creator, let $n_{u,i}(t)$ be its count in the eligible pre-target history, and let $n_{u,\max}(t)$ be the largest such creator-specific count for user $u$. Define a long-term relationship strength as $\mathrm{Long}(u,i,t)=n_{u,i}(t)/\max\{1,n_{u,\max}(t)\}$. For the ordered last $K_s=10$ eligible user--creator interactions, let $d$ be the reverse interaction index ($d=0$ for the most recent). The short-term component is $\mathrm{Short}(u,i,t)=\max_{\{d:i_d=i\}}\exp(-d/3)$, with a maximum over an empty set defined as zero. Hence repeated appearances contribute their most recent decayed strength rather than an unbounded sum.

The popularity component $\mathrm{Pop}(i)$ is derived from eligible training-split creator counts by applying $\log(1+n_i)$ and min--max scaling over observed creators; unseen creators receive zero. The fixed specialist score is
\begin{equation}
s_M(u,i,t)=
0.45\,\mathrm{Short}(u,i,t)
+0.45\,\mathrm{Long}(u,i,t)
+0.10\,\mathrm{Pop}(i).
\label{eq:memory-scoring}
\end{equation}
The same component weights and short-term decay settings are retained in the transferred Twitch specialist and are not reselected using held-out test outcomes. The memory ranking is obtained by sorting these candidate scores; deterministic creator- or room-identifier ordering resolves equal scores under the respective platform's scoring protocol. For KuaiLive, room candidates inherit relationship components through their room-to-streamer mapping, so distinct rooms of the same creator may share the same memory score. In Twitch, candidates are streamers directly.

The three terms deliberately expose different evidence sources. In particular, the absence of a previous interaction with a target creator does \emph{not} imply that $s_M$ is zero, because popularity may still contribute. The specialist is held separately from the sequential base: it does not constitute an additional learned representation fused into $B$. Equation~\eqref{eq:memory-scoring} is an interpretable instantiation rather than a claimed new memory architecture, and its realized ranking gain is specific to the chosen $B$, $M$, cutoff, and candidate regime.

\subsection{Base-Relative Relationship-Evidence States}
\label{sec:framework-states}

We operationalize the diagnostic variable $S$ introduced in Section~\ref{sec:regime-decomposition} using the target creator and pre-target history. Let $V_L(x)$ indicate that the target creator occurs in the sequence visible to a base with input length $L$, and let $H(x)$ indicate that the same creator occurs anywhere in the eligible pre-target relationship history. Then
\begin{equation}
S_L(x)=
\begin{cases}
\text{represented},&V_L(x)=1,\\
\text{recoverable but unrepresented},&V_L(x)=0,\ H(x)=1,\\
\text{unavailable},&V_L(x)=0,\ H(x)=0.
\end{cases}
\label{eq:diagnostic-states}
\end{equation}
These states are exhaustive and mutually exclusive. The second state is also referred to as \emph{long-horizon-only} and the first as \emph{recent-visible} in the evaluation outputs. The classification is defined relative to the target creator and the particular base-visible sequence: it is not a fixed recency taxonomy shared across different input lengths or platforms. Moreover, appearing in the base input is not evidence that the trained model has perfectly encoded the corresponding relationship. The three labels are descriptive, not assumed to imply universal signs of specialist-minus-base utility.

Both indicators are computed after the target has been observed. In particular, neither the target-relative state $S_L$, its distance to the latest target-creator interaction, nor any realized target rank or $\Delta_m(x)$ is included in the serving feature vector $Z$. The mechanism analysis asks how the distribution of offline relative utility varies across these labels; it does not use them as a decision rule.

\subsection{Observable Features and Conditional Relative-Utility Estimation}
\label{sec:framework-estimation}

The estimator $\hat\eta_r(z)$ is trained to predict the realized development-event target $\Delta_m(x)$ defined by Eq.~\eqref{eq:delta-memory}. Its inputs comprise only pre-outcome user/history summaries and base-ranking descriptors. In the Twitch implementation, the six behavioral descriptors are log history length, repeated-creator rate, normalized preference entropy, old-versus-recent preference drift, temporal regularity, and a composite history-complexity measure. The eight base-score descriptors are candidate-score standard deviation and range, top-1 versus top-2, top-1 versus top-5, and top-10 versus top-11 score margins, top-score standardized value, normalized score entropy, and top-ten softmax mass. All eight use the eligible candidate scores for the current recommendation context. Behavioral-state summaries should not be confused with the target-relative diagnostic state $S_L$.

The history-complexity descriptor combines development-reference percentile transforms of entropy, preference drift, and log history length with weights $0.4$, $0.4$, and $0.2$. In the frozen external protocol, empirical-distribution references derived on development data are reused for test transformations; target-relative labels or test outcomes are never used to recompute the reference. This ensures that $\hat\eta_r$ receives a fixed-feature interpretation across the development-to-test boundary.

For the primary selector we use histogram-based gradient-boosted regression (HGB) with $200$ boosting iterations, learning rate $0.05$, maximum depth $3$, minimum leaf size $50$, and $\ell_2$ regularization $1$. Five-fold shuffled out-of-fold (OOF) predictions on the development set are used to select a threshold maximizing the development mean of the resulting switched NDCG@$10$ ranking, with ties favoring fewer invocations. The final regressor is fitted on all development instances; its fitted parameters, feature definitions, transformations, and OOF-selected threshold $\tau_r$ are then frozen before the independent test. KuaiLive uses analogous development-only utility estimation with candidate-regime-specific feature distributions and policies. The HGB architecture is an operational choice, not a claimed methodological novelty.

The estimator is not presented as a calibrated probability or an accurate per-event utility oracle. A pointwise threshold depends on the prediction scale and its stability across splits, whereas offline equal-budget ranking controls depend only on relative score order. These are different evaluation properties and are kept separate below.

\subsection{Specialist Selection and Matched-Budget Controls}
\label{sec:framework-controls}

The primary learned decision follows Eq.~\eqref{eq:utility-threshold}: it retains the base ranking unless the predicted specialist-minus-base advantage exceeds the development-frozen threshold, in which case the specialist's ranking replaces it. The decision uses base output and observable history descriptors before the target is known; a conceptual serving implementation needs to compute the memory ranking only after a positive invocation decision. The offline analyses also compute both rankings for every evaluated instance, solely to construct supervision, comparisons, and diagnostic strata.

Two controls characterize the learned selection. A \emph{base-difficulty} regressor uses the same observable feature family and model family to predict $1-u_K(B,x)$ from development instances. On the test set it selects, by an offline Top-$m$ operation, exactly as many events as the fixed utility policy happened to invoke, $m=\sum_i a_{\tau_r}(z_i)$. An \emph{Oracle} selects the same number of events by the realized specialist-minus-base utility $\Delta_m(x_i)$, yielding an analysis-only hindsight upper bound. Stable row-index tie-breaking makes these budget-matched controls deterministic. Neither uses future test targets to fit a predictor or reselect the learned utility threshold; Oracle uses test outcomes exclusively for the explicitly nondeployable upper-bound analysis.

This protocol separates a fixed-threshold \emph{pointwise policy} from \emph{batchwise offline controls}. The exact matched budget is therefore a condition on the controls, not a hard online invocation guarantee for the primary policy. A deployed system would incur base-ranking computation, selector overhead, and specialist scoring only on invoked events. Measured accuracy--invocation--latency trade-offs and any cost-sensitive extensions are evaluated separately rather than attributed to an untested calibrated cost model.
