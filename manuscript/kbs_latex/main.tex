\title{When Does Relationship Memory Help? Base-Relative Evidence Valuation for Live-Streaming Recommendation}

\author{Anonymous Authors}

\begin{abstract}
Persistent viewer--creator relationships may complement sequential recommenders, but their marginal ranking value depends on the incumbent and eligible candidates. We quantify the event-level NDCG@10 increment of a fixed Short--Long--Popularity relationship-memory specialist and predict its value from pre-outcome history and Base-score descriptors. On 44,221 frozen Twitch streamer-ranking events, a utility-based selector increases NDCG@10 from 0.58211 to 0.58983 with 15.04\% Memory invocations. On 10,222 paired KuaiLive room events, Memory-minus-Base value reverses from $-0.04120$ under sampled-active candidates to $+0.04631$ under full-active candidates. Exploratory M3 development analyses show that candidate-aligned supervision reallocates specialist calls across 21--23\% of requests. On 30,000 additional, previously unevaluated M3 author-ranking targets from the same collection period, frozen full-candidate-supervised selectors improve full-ranking NDCG@10 over sampled-supervised selectors by 0.00539 (SASRec) and 0.00359 (GRU4Rec), with fewer realized Memory calls. On a nested 4,096-target cohort, original relationship memory exceeds three time- and activity-preserving history randomizations by 0.03115 NDCG@10 under identical full-active candidates. The original frozen M3 evaluation also favors relative-utility selection over four specified alternative objectives across six fitted incumbents. Unconditional Memory nevertheless remains more accurate and faster in the recorded M3 warmed scoring replay than selective routing. These findings establish candidate-conditioned, incumbent-relative knowledge valuation and its decision relevance under stipulated invocation constraints, without asserting a new generic routing algorithm or measured deployment-cost savings.
\end{abstract}

\section{Introduction}

Sequential recommendation models recover behavioral preferences from recent and recurrent interactions, but the knowledge needed for an individual decision can extend beyond the model's input window \cite{kang2018sasrec,sun2019bert4rec}. Live-streaming recommendation makes this distinction consequential: available broadcasts change over time, while relationships between viewers and creators persist across sessions. A historical viewer--creator relationship source can therefore supply evidence that a sequential recommender has not represented, or repeat evidence the incumbent already captures. The relevant knowledge-system question is not how well that source ranks in isolation, but \emph{when using it improves the incumbent's decision among the candidates actually available}.

Research on knowledge-enhanced recommendation has developed powerful mechanisms for incorporating heterogeneous information into representations, while memory-management methods determine which interactions should be retained for subsequent personalization \cite{xie2026mhgfcl,zhong2026samd}. Learning-to-defer and adaptive recommendation routing address the related decision of when an additional expert should be invoked \cite{mozannar2020defer,mao2024regression,yuan2026dsframe}. These developments motivate a more specific evaluation object: the \emph{incremental downstream ranking value of an already specified knowledge source}, relative to a designated Base recommender. This object links knowledge availability to the actual consequence of choosing one complete ranking over another, rather than treating standalone specialist accuracy, Base uncertainty, and incremental benefit as interchangeable quantities.

For a ranking event with eligible candidates $C$, we define relationship-knowledge value as the event-level top-$K$ utility of a fixed historical Memory ranker minus that of the trained incumbent, both evaluated on $C$. This value depends jointly on the knowledge contained in the pre-event relationship history, what the incumbent already represents, and which alternatives compete for a top-ranked position. The candidate component is particularly important: evaluating rankings on a sampled subset need not preserve the relative ordering of models on the full available set \cite{krichene2020kdd}. The resulting methodological issue concerns not only reporting sampled metrics, but also \emph{which candidate-regime utility label is used to supervise a knowledge-use decision}. A value predictor can use pre-outcome historical and Base-score descriptors, whereas the observed target and the resulting utility labels are available only for learning and offline evaluation.

A candidate-aligned valuation target creates two complementary empirical questions. First, does predicting the specialist's incremental utility lead to more effective choices about using it on the actual candidates, compared with selection signals based on incumbent difficulty or specialist quality? Second, does the authentic relationship history itself contain useful ranking information when the current candidate universe and Memory scorer are held fixed? The second question assesses the source of the knowledge signal: it is a parallel validity test of the same historical specialist, not a downstream consequence of the selector's success. Figure~\ref{fig:knowledge-value-chain} summarizes these distinct roles.

We address these questions using three live-streaming ranking protocols with explicitly different evidentiary purposes. Twitch/LiveRec provides streamer-ranking evidence about historical complementarity; an original KuaiLive room-ranking protocol supplies a paired sampled-versus-full candidate comparison; and KuaiLive-M3 supports frozen author-ranking decisions across trained SASRec and GRU4Rec incumbents \cite{rappaz2021liverec,qu2026kuailive}. The M3 analyses include an initial forward-time evaluation and separately frozen, previously unevaluated targets drawn from the same source recording period. Those additional targets test candidate-aligned supervision on 30,000 events and the effect of authentic versus constrained-randomized historical relations on a nested 4,096-event cohort. Together the protocols distinguish historical value, decision quality and source validity without assuming that streamer, room and author ranking are equivalent tasks.

Our contributions are three connected empirical findings about the use of fixed relationship knowledge:
\begin{itemize}
    \item \textbf{Incumbent- and candidate-relative valuation.} We operationalize event-level historical-knowledge value as a difference between complete rankings from the same designated Base--Memory pair on the same eligible alternatives, and characterize historical complementarity and candidate-regime dependence through streamer and paired room-ranking evidence.
    \item \textbf{Candidate-aligned supervision for knowledge use.} We connect this valuation target to pre-outcome specialist selection, testing decision consequences across frozen author-ranking incumbents and demonstrating stronger full-candidate selection from full-candidate, rather than sampled-candidate, utility supervision on the additional M3 targets.
    \item \textbf{Fixed-candidate verification of historical-source information.} We test the contribution of the authentic viewer--creator history against time- and activity-constrained alternatives while retaining the same full-active candidates and ranking implementation, establishing a separate source-validity check for the knowledge being valued.
\end{itemize}

\section{Related Work}

\subsection{Knowledge Representation, Relationship Memory, and Memory Management}

Sequential recommenders learn preference structure from ordered interactions, including attention-based and multi-interest models \cite{kang2018sasrec,sun2019bert4rec,ni2025idmarec,sheng2025dsmgrec}. Knowledge-aware recommendation extends that representation with auxiliary relational evidence. CKLF combines knowledge-graph propagation and sequential interests \cite{chen2024cklf}; MHGFCL learns collaborative, semantic and structural knowledge views and adaptively fuses their representations \cite{xie2026mhgfcl}; and KAPER selects informative graph paths for preference-aware reranking \cite{kim2026kaper}. These approaches primarily determine how the recommender represents or integrates additional knowledge.

A distinct line of work manages the knowledge that remains available to personalization systems. Scene-aware memory discrimination (SAMD) selects personal interactions to retain according to application demands and evaluates their effects on downstream personalized applications \cite{zhong2026samd}. MemRec organizes collaborative memory for LLM-based recommendation \cite{chen2026memrec}, while denoising and reliability-aware approaches address the quality of auxiliary signals entering the recommendation model \cite{peng2025negative,zhu2026mifusr,zhang2026mcd4sr}. The downstream usefulness of retained or fused evidence motivates a complementary measurement problem for a source that is already available: evaluate its marginal contribution to the ranking made by a specified incumbent. We keep the historical relationship ranker separate and auditable so that its use-time contribution can be observed through alternative complete ranking outputs. This view is consistent with decision-theoretic accounts of information value, which relate information to its consequences for an action \cite{abbas2025voi}.

\subsection{Utility-Based Expert Selection and Adaptive Inference}

Learning-to-defer provides established methods for delegating individual decisions to complementary predictors. Consistent deferral estimation, post-hoc selection and regression-based multiple-expert formulations show how relative performance, losses and invocation costs can enter such decisions \cite{mozannar2020defer,narasimhan2022posthoc,mao2024regression,mao2025mastering}. In sequential recommendation, DS-Frame combines fast inference with iterative latent refinement and a learned selector under a computation budget \cite{yuan2026dsframe}. These results establish the methodological basis for conditional specialist use.

The unresolved issue in our setting is the \emph{supervision target for an external, fixed relationship-knowledge source}. Predicting the incumbent's difficulty, the Memory ranker's standalone success or a Base score margin supplies different information from predicting the realized ranking-utility difference between the two experts. Methods based on recommender uncertainty, including LLM-guided approaches such as GUIDER, provide additional selection precedents \cite{xu2026guider}. Our comparison holds the incumbent, specialist and full candidate environment fixed when evaluating the consequences of different supervision objectives. A specialist-call quota specifies the decision setting; the economic or latency benefit of enforcing that quota is an empirical system question distinct from the quality of the resulting ranking choices.

\subsection{Candidate-Dependent Ranking in Live Recommendation}

Live-streaming ranking combines persistent viewer--creator interests with time-dependent room availability and repeated viewing. LiveRec models the live consumption setting \cite{rappaz2021liverec}; KuaiLive links room sessions with persistent streamer identities \cite{qu2026kuailive}; and DCGLive studies interactions among users, rooms and creators \cite{guo2026dcglive}. Additional studies of repeated consumption and time-dependent engagement underscore the relevance of long-term history in a changing recommendation environment \cite{gao2023driver,zhu2025repeated}. These platforms support different evaluation units: Twitch streamers, original KuaiLive rooms and M3 persistent authors. Their results can illuminate the same knowledge-use question without implying identical datasets or evaluation populations.

Ranking utility is itself sensitive to which alternatives are evaluated. Krichene and Rendle establish that sampled ranking metrics can fail to preserve relative model comparisons with full-ranking evaluation \cite{krichene2020kdd}. For knowledge-use decisions, this result has an additional implication: a label indicating that Memory improves on Base for sampled candidates may disagree with the corresponding label on the available full candidate universe. Our paired room-ranking comparison examines this dependence for one fixed Base--Memory pair and separates candidate-membership changes from the score-normalization reference. The subsequent author-ranking study tests whether training on the actual full-active candidate regime produces better \emph{use-time specialist selection}, while a separate historical-null comparison tests whether the original relationship source contributes information under that fixed regime.

Taken together, existing work motivates learning what knowledge to represent or retain, when to delegate a decision and how ranking metrics change with candidate sampling. This study joins those questions at a measurable interface: the candidate-indexed downstream value of a fixed historical relationship source relative to its incumbent, its prediction from decision-time information, and the validity of the history that supplies it.

\section{Knowledge Valuation and Selective Use}
\label{sec:problem}
\label{sec:framework}

We study the use of an already specified relationship-knowledge specialist for a ranking decision. The framework fixes the incumbent, the historical source and the evaluation candidates before asking whether to use the specialist. Its central quantity is the specialist's incremental ranking utility on those candidates; observed outcomes provide offline supervision, whereas decision-time features alone determine invocation. Figure~\ref{fig:framework} separates these two information paths.

\subsection{Ranking Events and Candidate-Dependent Utility}
\label{sec:event-utility}

For user $u$, decision time $t$ and candidate regime $r$, let $\xi_r=(u,t,\mathcal{C}^{(r)}_{u,t},\mathcal{H}_{u,t})$ denote the pre-outcome context. The set $\mathcal{C}^{(r)}_{u,t}$ contains the eligible ranking alternatives and $\mathcal{H}_{u,t}$ the interactions observed strictly before $t$. An offline evaluated event is $x_r=(\xi_r,y)$, where $y$ is the subsequently observed target in that eligible set. Rankers operate on $\xi_r$ without seeing $y$; the target is used only to evaluate their outputs. Candidate regime $r$ specifies how candidates and their scores are constructed, and a given event can be evaluated under more than one regime. We suppress $r$ when it is fixed.

Let $r_A(y\mid\xi)$ be the one-indexed position of target $y$ in the candidate ranking returned by model $A$. For one observed relevant item, event-level normalized discounted cumulative gain at cutoff $K$ is
\begin{equation}
    u_K(A,x)=
    \begin{cases}
        \displaystyle \frac{1}{\log_2\!\left(r_A(y\mid\xi)+1\right)}, & r_A(y\mid\xi)\le K,\\[6pt]
        0, & r_A(y\mid\xi)>K.
    \end{cases}
    \label{eq:event-ndcg}
\end{equation}
Mean NDCG@$K$ is calculated across an explicitly specified evaluation sample, with $K=10$ throughout the experiments. Since ranks depend on the eligible alternatives, changing the candidate regime may change the observed value of the same ranker without changing its historical evidence or scoring function.

\subsection{Fixed Incumbent and Explicit Relationship Knowledge}
\label{sec:framework-base}
\label{sec:framework-memory}

The trained \emph{Base} ranker $B$ is the designated incumbent within each dataset's evaluation protocol. Twitch uses availability-aware LiveRec \cite{rappaz2021liverec}; the original KuaiLive room-ranking model combines room- and creator-identity SASRec branches, standardizing scores within each candidate set before their development-selected fusion; and KuaiLive-M3 uses author-ranking SASRec and GRU4Rec. These are protocol-specific trained models, not a single incumbent transferred between streamer-, room- and author-ranking tasks. Their training and checkpoint-selection procedures are described in Section~\ref{sec:experimental-setup} and Supplementary S2--S3.

The \emph{Memory} ranker $M$ is a fixed and auditable specialist defined by prior user--creator relationships. Let $n_{u,i}(t)$ count interactions with creator $i$ before the event and $n_{u,\max}(t)=\max_j n_{u,j}(t)$ across eligible recorded history. The long-term score is $\mathrm{Long}(u,i,t)=n_{u,i}(t)/\max\{1,n_{u,\max}(t)\}$. For the user's last $K_s=10$ creator interactions, indexed backward from the most recent by $d=0$, define $\mathrm{Short}(u,i,t)=\max_{\{d:i_d=i\}}\exp(-d/3)$, with zero if no matching event exists. The popularity component $\mathrm{Pop}(i)$ is the log-count transform of TRAIN-split creator frequency followed by min--max scaling; it is zero for a creator absent from that reference. The specialist score is
\begin{equation}
s_M(u,i,t)=
0.45\,\mathrm{Short}(u,i,t)
+0.45\,\mathrm{Long}(u,i,t)
+0.10\,\mathrm{Pop}(i).
\label{eq:memory-scoring}
\end{equation}
The weights remain fixed across ranking events and the specialist does not retrain or fuse its coefficients for a particular user. Eligible rooms in the original KuaiLive protocol may share a creator-level score, whereas Twitch and M3 rank persistent streamer or author identities directly. In M3, Short uses the last ten \emph{all-author} interactions, and Long's history normalization considers past authors even if they are not in the current TRAIN-known vocabulary. Such historical observations affect recency and normalization, but they do not create additional eligible current candidates. Both $B$ and $M$ rank the \emph{same} event-specific candidates; eligibility and tie-breaking rules are recorded in Section~\ref{sec:exp-data} and Supplementary S1--S2.

\subsection{Incumbent-Relative Knowledge Value and Candidate Regimes}
\label{sec:relative-utility}
\label{sec:conditional-utility}

Knowledge value is defined as the difference between two fully specified ranking decisions, rather than the specialist's isolated predictive quality. For the same event and eligible candidates, write
\begin{equation}
    \Delta_M(x)=u_K(M,x)-u_K(B,x).
    \label{eq:delta-memory}
\end{equation}
Positive or negative values mean that replacing $B$ with $M$ improves or worsens the realized top-$K$ rank utility. The target-dependent $\Delta_M$ is observable during supervised development and offline evaluation; it is \emph{not} itself a decision-time feature.

Let $Z$ denote features computed from pretarget history, current candidate availability and Base scores. The regime-specific conditional value function is
\begin{equation}
    \eta_r(z)
    =\mathbb{E}\!\left[\Delta_M(X)\mid Z=z,R=r\right].
    \label{eq:eta}
\end{equation}
A model fitted to these labels yields $\hat{\eta}_r(z)$ as the decision-time prediction of using $M$ instead of $B$. Candidate regime is part of the value target even if the selector is not given a separate categorical regime indicator.

For the paired development tasks, $\Delta_S$ and $\Delta_F$ are the incremental utilities measured on sampled and full-active candidate sets, respectively. An observed target may be retained in a retrospectively constructed sampled \emph{training label}; this construction is separate from the information available to a deployed selector. Let $\pi_S$ and $\pi_F$ be policies trained and calibrated under their respective labels and evaluated on the same full-active events. Define $V_F(\pi)=\mathbb{E}[u_{10}(B,X_F)+\pi(Z)\Delta_F(X)]$. The policy transfer comparison is
\begin{equation}
    \mathcal{R}_{S\rightarrow F}
    =V_F(\pi_F)-V_F(\pi_S),
    \label{eq:candidate-supervision-transfer}
\end{equation}
This is a contrast between the realized full-candidate performance of \emph{frozen fitted policies}, not an identity guaranteeing that aligned supervision is superior or that their realized specialist-call rates are equal.

\subsection{Pretarget Estimation and Observable Evidence}
\label{sec:framework-estimation}

The feature vector $Z$ combines summaries of historical creator repetition and support with the incumbent's score distribution over the currently available candidates. These descriptors characterize the knowledge that could be useful and the incumbent decision it could change. The Twitch selector uses six history and eight Base-score features, while M3 uses seven history/candidate and five Base-score features; the fitted estimators and candidate-scoring pipelines are protocol-specific. M3's historical-support share, for example, is derived from creator identities already observed and the current candidate roster, \emph{before} computing the full Memory ranking.

Training labels contain the subsequently observed target and its realized ranking positions, but no such target-specific information enters $Z$. The same separation applies to features that could only be calculated from the true target's membership in the Base's input or historical sequence: these are reserved for retrospective diagnostics. Section~\ref{sec:exp-comparators} specifies the fitted estimators and comparator targets; full feature transformations and audit rules appear in Supplementary S2 and S7.

\subsection{Invocation-Constrained Use and Retrospective Diagnostics}
\label{sec:decision-rule}
\label{sec:framework-controls}

A policy first computes the Base ranking and the observable features. For each event it either returns $B$ or computes the ranking from $M$ using the identical eligible candidates. Denoting this pretarget decision by $a(Z)\in\{0,1\}$, the realized selected utility is $u_K^{\mathrm{sel}}(x;a)=(1-a)u_K(B,x)+a\,u_K(M,x)$. Taking expectations conditional on a regime yields
\begin{align}
    &\mathbb{E}\!\left[u_K^{\mathrm{sel}}(X;a)-u_K(B,X)\mid R=r\right] \\
    &\qquad=\mathbb{E}\!\left[a(Z)\Delta_M(X)\mid R=r\right]
    =\mathbb{E}\!\left[a(Z)\eta_r(Z)\mid R=r\right].
    \label{eq:expected-selective-gain}
\end{align}
This standard identity connects the conditional value target with decision quality and is consistent with established learning-to-defer formulations \cite{mozannar2020defer,narasimhan2022posthoc}; it is not a claim of a new general delegation theorem.

The Utility policy compares the fitted gain estimate with a DEV-selected threshold. With $\succeq_r$ denoting the protocol's deterministic boundary convention, the policy is
\begin{equation}
    a_{\tau_r}(z)=\mathbf{1}\!\left[
    \hat{\eta}_r(z)\mathrel{\succeq_r}\tau_r
    \right].
    \label{eq:utility-threshold}
\end{equation}
A threshold is chosen on development data for an invocation-fraction design limit $q_r$: $\hat q_{\mathrm{DEV}}=n_{\mathrm{DEV}}^{-1}\sum_i a_{\tau_r}(z_i)\le q_r$. Calibration constrains the \emph{development} call count and does not guarantee an identical realized fraction on the evaluation cohort. It is a limit on specialist invocations, rather than an observed cap on production compute time or monetary expense. The same frozen Base--Memory pair supports comparisons with predicted Base difficulty, standalone Memory performance and available pretarget heuristics; see Section~\ref{sec:exp-comparators}.

\paragraph{Retrospective relationship-evidence states.}
\label{sec:framework-states}
Let $V_L(x)$ indicate that the \emph{observed target creator} occurs in the Base's most recent $L$ input interactions, and let $H(x)$ indicate that the creator occurs in eligible earlier user history. For explanatory analysis after the target outcome, define
\begin{equation}
S_L(x)=
\begin{cases}
\text{represented},&V_L(x)=1,\\
\text{recoverable but unrepresented},&V_L(x)=0,\ H(x)=1,\\
\text{unavailable},&V_L(x)=0,\ H(x)=0.
\end{cases}
\label{eq:diagnostic-states}
\end{equation}
The three states distinguish evidence represented in the input window, recoverable outside that window and not observed in accessible history. The label \emph{represented} describes sequence membership, not proof that the trained embedding retained every relationship. Since these states depend on the observed target, they are \emph{never} features for the real selector.

\paragraph{Regime-level retrospective decomposition.}
\label{sec:regime-decomposition}
Let $S$ denote the preceding mutually exclusive historical-evidence states. Their contribution to mean specialist value obeys
\begin{equation}
    \bar{\Delta}_r
    =\sum_s P(S=s\mid R=r)
    \,\mathbb{E}\!\left[\Delta_M(X)\mid S=s,R=r\right],
    \label{eq:regime-decomposition}
\end{equation}
The decomposition separates state prevalence from conditional Memory--Base utility. It supports retrospective candidate-regime analysis (Section~\ref{sec:exp-regimes}) and does not enter decision-time features or introduce another training target.

\section{Experimental Design}
\label{sec:experimental-setup}

We evaluate three empirical questions about a fixed relationship-knowledge source: how its incremental value depends on the incumbent and candidates (RQ1), whether candidate-aligned value supervision improves specialist selection (RQ2), and whether authentic historical relations contribute information when current candidates are held fixed (RQ3). The protocols differ in ranked unit, sampling design and inferential status. Table~\ref{tab:exp-datasets} identifies these differences before the model comparisons and statistical tests are specified.

\subsection{Ranking Tasks and Evidence Hierarchy}
\label{sec:exp-data}

\paragraph{Twitch/LiveRec: historical complementarity and frozen selection.}
In an availability-aware, ten-minute observation-step protocol, Twitch ranks eligible persistent streamers \cite{rappaz2021liverec}. The filtered data comprise 46,878 development (DEV) and 44,221 held-out TEST requests, each with one recorded relevant streamer. LiveRec uses the 16 most recent input interactions, while relationship histories contain only interactions preceding the target observation. Eligibility is determined by the recorded crawl-step boundary; these records do not establish exact physical session entry or exit. Training data determine the Memory popularity reference (Supplementary S1). The observed target is used to score the frozen ranking and retrospectively characterize evidence recoverability, never to construct an online selector feature.

\paragraph{Original KuaiLive: a paired room-candidate diagnostic.}
The original KuaiLive protocol ranks an active \emph{room}, although relationship knowledge is indexed by its persistent creator \cite{qu2026kuailive}. A per-user chronological leave-last-two-out split yields 10,222 eligible users and paired DEV/previously examined TEST room targets. The sampled-active evaluation ranks the positive alongside 574 distinct active non-target rooms (575 total); the full-active evaluation uses the recorded contemporaneous active room roster. Half-open session intervals determine candidate availability, with the observed positive retained when its source interval conflicts with the event. Sampled alternatives are not assumed to be verified disliked items. The same 10,222 previously examined TEST events, Base checkpoint and Memory history are used in both candidate regimes. This is a \emph{retrospective, within-event candidate-regime comparison}, not an additional prospectively frozen room-ranking TEST.

\paragraph{KuaiLive-M3: original forward-time author ranking.}
M3 ranks persistent \texttt{author\_id} identities; active room sessions determine which TRAIN-known authors are available at a decision. The recorded-time TRAIN boundary is 23 March 2026, 12:00, and DEV ends on 27 March 2026, 14:00; the subsequent interval supplies TEST targets. No time zone absent from source metadata is imputed. From 24,995,148 eligible TRAIN interactions, a deterministic outcome-independent construction provides 50,049 DEV and 47,575 original TEST requests, the latter from 12,533 users. Each selected target belongs to the TRAIN-known author vocabulary and has at least two earlier valid user interactions. The full-active candidate set contains all distinct TRAIN-known authors with at least one active room at the event time (median 31,065 authors on original TEST). The separate 4,096-request, 575-author DEV panel selects neural checkpoints; it is not the full-active TEST ranking environment. The globally chronological split does not make users disjoint across time.

\paragraph{M3 additional targets and auxiliary analyses.}
A separate pre-outcome freeze selected 30,000 additional author-ranking targets (10,387 users) from the \emph{same} original March 2026 TEST-source collection interval, with no overlap in \emph{evaluated event IDs} with the 47,575 original TEST requests. A nested 4,096-target/3,059-user sample tests authentic versus perturbed relationship history. Neither sample is a newly collected later-period TEST; users and earlier interaction streams may overlap the initial evaluation. M3 exploratory DEV analyses compare candidate-supervision regimes and historical components; additional DEV historical nulls assess source controls. A matched 256-request DEV hardware replay measures scoring-path time, not online service cost. Their specific methodological roles are kept separate from the original forward-time and additional-target inference.

\subsection{Fixed Rankers and Selection Objectives}
\label{sec:exp-comparators}

Each evaluated event is ranked by a designated trained Base and the fixed Short--Long--Popularity Memory on \emph{the same available alternatives} (Section~\ref{sec:framework}). The Twitch incumbent is availability-aware LiveRec; the original KuaiLive room incumbent is the development-selected Dual-ID SASRec fusion; and M3 uses author-ranking SASRec or GRU4Rec with three separately trained initialization seeds (20261012, 20261013 and 20261014). The six M3 fits share the original TEST requests; they measure checkpoint robustness rather than six independent test populations.

To distinguish estimated marginal knowledge value from general recommendation difficulty, the supervised policies predict either \emph{Utility}, $u_{10}(M,x)-u_{10}(B,x)$; \emph{Difficulty}, $-u_{10}(B,x)$; or \emph{Specialist Quality}, $u_{10}(M,x)$. M3 additionally uses two pretarget heuristic scores: \emph{Uncertainty}, the negative Base top-two ranking-score margin, and \emph{History}, the user's previous interaction count. The margin is a heuristic, not a separately calibrated uncertainty estimator. Always Base and Always Memory form unconditional references. Random@budget is an expected-allocation control, and the hindsight Oracle uses realized outcomes only as an offline upper bound. Utility, Difficulty and Specialist Quality share the relevant protocol's regression class and available pre-outcome feature family; their prediction targets, not the underlying Base or Memory rankers, differ.

\subsection{Development Calibration and Pre-Outcome Information}
\label{sec:exp-freeze}

Neural incumbents and the deterministic Memory formulation are fixed before the corresponding held-out evaluation. Twitch uses five DEV out-of-fold (OOF) partitions for utility regression and freezes the Utility threshold before TEST. The Twitch Difficulty and hindsight Oracle references retrospectively match the \emph{realized Utility TEST Memory-call count}; they are equal-count quality controls, not independently frozen deployable policies. The original room experiment reuses previously examined TEST events solely for its paired candidate diagnostic.

For each of the six original M3 Base fits, a common sampled-candidate DEV screening panel selects the neural checkpoint, while five \emph{user-group-disjoint} DEV OOF folds train and calibrate each supervised selection objective on full-active ranking events. Five policy scores (the three fitted objectives and two deterministic heuristics) receive independently chosen, inclusive-tie thresholds maximizing DEV OOF incremental ranking utility subject to at most 30\% DEV Memory invocations. These thresholds and predictors are fixed before the 47,575-event original TEST. The policy is applied pointwise without using outcomes, recalibrating on TEST, or selecting the top requests of a TEST batch. Consequently a common DEV cap does not imply equal realized TEST call fractions, which may exceed 30\%.

M3 ranking and history updates follow recorded event time. Past interactions, including TEST-period observations that have already occurred but are not among evaluated TEST target events, may update a subsequent request's history. No current or future outcome participates in the live candidate set, Base/Memory scoring, policy descriptors or threshold selection. Candidate rank ties use a deterministic author-identity convention. The saved decisions and rank outputs precede revelation of their corresponding target for metric computation. This causal information boundary differs from the retrospective sampled \emph{training-label} construction, where the observed author is retained in the sampled DEV ranking roster solely to define $\Delta_S$. The latter is never used as an online candidate generator or a predictor feature (Supplementary S1--S2).

\subsection{Candidate-Regime and Historical-Source Controls}
\label{sec:exp-regimes}

\paragraph{Room-ranking candidate-regime comparison (RQ1).}
For original KuaiLive, the same histories, targets and fixed raw Base/Memory scorers are evaluated on sampled-active $S$ and full-active $F$ candidates. The Base combines its branches after a score standardization whose candidate reference may vary with the roster. Event-level sampled-to-full changes are
\begin{equation}
D_i =
\big[u_{10}(M,x_i^{\mathrm{full}})-u_{10}(B,x_i^{\mathrm{full}})\big]
-
\big[u_{10}(M,x_i^{\mathrm{sampled}})-u_{10}(B,x_i^{\mathrm{sampled}})\big].
\label{eq:paired-regime-shift}
\end{equation}
To distinguish membership from score-normalization reference, write $g_i(C,R)$ for Memory-minus-Base utility with ranked candidates $C\in\{S,F\}$ and score-reference roster $R\in\{S,F\}$. Order-averaged allocations are
\begin{align}
A_{C,i}&=\tfrac12\big[g_i(F,S)-g_i(S,S)+g_i(F,F)-g_i(S,F)\big],\nonumber\\
A_{R,i}&=\tfrac12\big[g_i(S,F)-g_i(S,S)+g_i(F,F)-g_i(F,S)\big].
\label{eq:factorial-allocations}
\end{align}
This is a within-event accounting of the observed regime shift: candidate membership changes the number, identities and competitive ranks of alternatives jointly. Three checkpoint pairs and nine sampled candidate draws on the same previously examined room cohort provide sensitivity checks (Supplementary S5 and S8), not new independent TEST populations.

\paragraph{Exploratory M3 supervised-label transfer (RQ2).}
A distinct DEV analysis uses the original 50,049 full-active M3 author-ranking DEV events from 12,628 users and primary SASRec/GRU4Rec Base seeds. Holding the trained Base, deterministic Memory and twelve full-active pretarget features fixed, a five-outer/four-inner \emph{user-disjoint} design fits and calibrates sampled-label $S\!\rightarrow\!F$ and full-label $F\!\rightarrow\!F$ selectors. The sampled label retains the target retrospectively, whereas all policies are evaluated on identical full-active candidates using target-blind features. An adapted condition uses full-active labels from outer-training users and is not an unsupervised or label-free transfer. Inner DEV caps are 30\%; outer call fractions arise naturally. These HGB fits use 120 iterations rather than the original M3 policies' 200. Follow-up DEV source-component (Long-only, Short-only, TRAIN-popularity and placement) and reduced-feature controls provide exploratory mechanisms; 2,000 paired user-cluster bootstrap replicates describe their differences (Supplementary S10). They are not new chronological TESTs or members of the original TEST hypothesis family.

\paragraph{DEV historical identity perturbation (RQ3).}
The historical-source diagnostic freezes 1,024 requests from 992 DEV users in 16 pretarget-time/activity strata, excluding a preceding 128-request feasibility pilot. An original Full/Long scorer parity check precedes constrained null construction. Historical author labels are exchanged between different viewers within the same source hour, preserving each viewer's observed event times and counts, source author-hour totals and contemporaneous creator availability. A swap affects target histories only after its source hour fully closes; the active source hour stays authentic. Three fixed seeds (20261014--20261016) leave the evaluated $F$ and retrospective $S$ candidate rosters unchanged. Original-versus-null Full Memory NDCG@10 on common $F$ candidates is analyzed with 2,000 paired user-cluster bootstrap draws per seed. These are three perturbations on \emph{one} DEV cohort, not population replicates. The DEV control also checks its own TRAIN-only Popularity ranking floor; that check does not substitute for a different cohort's prospective acceptance requirement (Supplementary S10.14 and S10.18).

\subsection{Additional-Target Freeze and Prespecified Comparisons}

To evaluate candidate-aligned supervision on targets not previously scored in the original M3 TEST, an outcome-blind selection freezes 30,000 eligible event IDs (10,387 users) drawn from the same previously studied March 2026 TEST-source interval. Selection is stratified into twenty population-weighted cells: five recorded source dates crossed with four within-date \emph{pretarget-history} quartiles, with 1,500 selected events per cell. Event selection uses source identities and earlier-observable activity, not current target authors or model utility. A nested, independently frozen 4,096-event subset (3,059 users) supports the historical-source test. Neither selection creates new future-period source data or user-disjoint replication.

For each primary original M3 Base family (SASRec and GRU4Rec, checkpoint seed 20261012), the sampled-supervised and full-supervised gates use the same fixed Base/Memory pair and twelve \emph{full-candidate} decision-time features. Their four-fold user-disjoint DEV OOF scores determine separate thresholds under the nominal 30\% DEV call limit. Gate structure and capacity are held constant; the labels differ because sampled training utilities are calculated with target-retained DEV subsets, whereas full labels use complete active candidates. Four final predictors, thresholds and target-blind rankings were sealed before the additional-event author outcomes were revealed. All four choices are evaluated on the same original full-active candidates, without test-time threshold adjustment or equalizing realized calls after the fact.

For the 4,096 nested targets, the unchanged original Full Memory scorer uses either the authentic historical source or three previously sealed, closed-hour historical author-label permutations. Each condition ranks identical full-active candidates, with source event times, author-hour activity margins and candidate availability preserved as specified in the DEV control. The three nulls are alternate histories of the \emph{same} target sample. The original protocol included a cohort-specific, pre-unseal comparison to TRAIN-only Popularity as a nondegeneracy acceptance condition; **this additional cohort's Popularity margin was not scored and sealed before the outcome revelation**, so that original condition is not retrospectively certified. The completed DEV popularity control and other observed null nonfloor diagnostics do not establish the missing acceptance check (Supplementary S10.15--S10.18).

\subsection{Endpoints, Statistical Inference, and System Measurements}
\label{sec:exp-statistics}
\label{sec:exp-implementation}

The primary rank endpoint is event-level NDCG@10 (Eq.~\eqref{eq:event-ndcg}); secondary reporting includes HR@10 and the observed Memory invocation fraction. All stated ranking comparisons are paired by evaluated event, and uncertainty estimation resamples at the user level. Target-relative evidence states (Eq.~\eqref{eq:diagnostic-states}) and recurrence are assigned retrospectively; they do not enter a live selector. Oracle and random allocation at a given call level provide hindsight and expected-allocation references.

Twitch TEST reports 5,000 user-paired bootstrap replicates. The paired original KuaiLive room candidate shift uses 3,000 paired user resamples. For the initial M3 47,575-event/12,533-user TEST, 5,000 user-cluster paired bootstrap draws form percentile intervals, and 5,000 user-cluster sign randomizations provide one-sided tests under an approximate within-user sign-symmetry assumption. The original M3 predeclared family compares Utility against Always Base, Difficulty and Specialist Quality, with Holm adjustment \cite{holm1979} for three comparisons \emph{separately within each} of the six Base--seed fits. Shared evaluation users prevent interpretation as six independent population replications or blanket correction across eighteen tests. Uncertainty, History and Always Memory comparisons are additional evaluations.

For the 30,000 additional M3 target events, the twenty-cell poststratification estimator weights each sampled cell by its frequency in the eligible residual TEST-source population. User-cluster pairing is maintained in 5,000 bootstrap draws for two-sided 95\% intervals and 5,000 cluster sign randomizations for one-sided tests. Holm adjustment covers exactly three precommitted directional comparisons: SASRec full-supervised minus sampled-supervised ranking utility, the analogous GRU4Rec contrast, and authentic Full Memory minus the \emph{within-event mean} of three historical null utilities on the nested cohort. This is a distinct comparison family from the initial original TEST. Different realized F/S Memory-call counts are reported explicitly, not retrospectively equalized. The additional targets share the source recording period with the initial TEST and do not constitute external future-time validation.

The original KuaiLive Base comprises 64-dimensional ReChorus SASRec room/creator branches, one attention layer, four heads and maximum input length 50. LiveRec uses context length 16; M3 Base models use 64-dimensional embeddings, 16-item histories and one SASRec self-attention or GRU4Rec recurrent layer. Original Twitch and M3 supervised gates use histogram gradient boosting (200 iterations, learning rate 0.05, depth 3, minimum leaf size 50 and $\ell_2$ penalty 1); the later exploratory DEV gates use the explicitly different capacity reported above. Full training, history processing and reproducibility specifications remain in Supplementary S1--S3 and S7--S10.

A separately timed \emph{DEV-only} scoring experiment executes the original primary-seed SASRec pointwise Utility selector, Always Base and Always Memory on the same 256 distinct author-ranking requests, each repeated three times in counterbalanced order on an RTX 3090, with CUDA synchronization. Pretarget history-source scanning and author-roster construction are timed separately from the warmed per-request scoring paths (Supplementary S10.17). This is neither production end-to-end serving latency nor a timing evaluation of the additional-target vectorized F-aligned gate. Memory-call constraints, absolute ranking utility and realized computation time are therefore reported as different outcomes.
\section{Experimental Results}
\label{sec:results}

The results proceed from the incremental value of fixed relationship evidence, to the role of candidate availability in defining that value, to the consequences for pre-outcome selection and the authenticity of the historical source. Resource-constrained allocation and measured execution costs complete the empirical account.

\subsection{Heterogeneous Utility of Relationship Memory}
\label{sec:results-heterogeneity}

The ranking contribution of relationship memory is heterogeneous rather than uniformly positive. On 44,221 Twitch held-out streamer-ranking requests, unconditional Memory obtains NDCG@10 $0.53980$, below LiveRec Base at $0.58211$ (paired difference $-0.04232$, 95\% CI $[-0.04521,-0.03950]$). Yet the negative aggregate masks a substantial positive contribution for previously encountered creators outside the incumbent's visible input window.

Figure~\ref{fig:results-evidence-states} and Table~\ref{tab:results-evidence-states} show that Memory improves NDCG@10 by $+0.22045$ on the 5,539 \emph{recoverable-but-unrepresented} TEST events. Its contribution is $-0.01935$ on 24,285 represented events and $-0.18215$ on 14,397 unavailable events. These target-defined groups identify the conditional pattern after the outcome is observed; the online selector does not receive their labels. The recoverable-group gain demonstrates that older observed relationships can add ranking information even when the same fixed specialist underperforms on average.

In the distinct KuaiLive-M3 author-ranking TEST, Memory reaches NDCG@10 $0.34679$ on 47,575 events, exceeding each of six fitted SASRec and GRU4Rec incumbents ($0.25800$--$0.26065$). For the primary SASRec fit its advantage is $+0.08879$. Thus, the sign of aggregate Memory--Base value changes across the two held-out tasks. Because Base design, ranking unit, candidates and time protocol differ together, this contrast characterizes incumbent- and setting-relative knowledge value without assigning the difference to one isolated cause.

\label{sec:results-regimes}

\subsection{Decision Value of Predicting Relative Utility}
\label{sec:results-decision}

The candidate comparisons motivate a consequential test: whether a selector guided by the incremental value of \emph{this} Memory over \emph{this} Base makes better choices than one guided by general request difficulty or specialist quality. On Twitch, a DEV-frozen Utility rule selects Memory on 6,650 of 44,221 TEST requests ($15.04\%$) and improves NDCG@10 from Base $0.58211$ to $0.58983$ (paired gain $+0.00772$, 95\% CI $[+0.00641,+0.00903]$). HR@10 increases by $+0.00945$ (95\% CI $[+0.00776,+0.01117]$). The DEV-trained Difficulty score reaches NDCG@10 $0.58340$ at the retrospectively matched TEST count, producing a Utility advantage of $+0.00644$ (95\% CI $[+0.00528,+0.00762]$). Unlike Utility's frozen pointwise threshold, Difficulty retrospectively ranks the entire TEST batch to achieve the same call count.

Memory contributes $+0.05136$ NDCG@10 on Utility-selected Twitch requests but $-0.05890$ on the remaining requests, whereas Difficulty's count-matched selections gain only $+0.00855$ on average. The nondeployable outcome-informed Oracle yields $0.64806$ NDCG@10 at the same call count. These observations establish decision relevance while leaving considerable predictive headroom.

\label{sec:results-robustness}

The source of historical knowledge is also relevant to its measured ranking value. For matched M3 development events, Full Memory is better than Long-only under full-active candidates ($0.343509$ versus $0.333231$ NDCG@10), whereas Long-only ranks ahead under retrospective sampled candidates ($0.773602$ versus $0.668498$; Table~\ref{tab:results-m3-dev-source}). Under original twelve-feature policies, Long-only incurs a larger candidate-supervision transfer loss than Full Memory ($0.010605$ versus $0.006159$ for SASRec and $0.010262$ versus $0.004970$ for GRU4Rec). In six-feature candidate-plus-Base controls, the Full-Memory transfer losses decrease to $0.001814$ and $0.001607$; these feature panels differ in information content, so the contrast does not identify an isolated causal mechanism. Short-only transfer also produces a large change in actual Memory calls; popularity and history-placement controls have near-zero invocation floors. A matched user-cluster analysis of fixed source utility clarifies the candidate-regime dependence: Full minus Long-only averages $+0.010278$ under $F$ (95\% CI $[+0.007906,+0.012668]$) and $-0.105104$ under retrospective $S$ (CI $[-0.108326,-0.101683]$), giving a paired source--regime interaction of $+0.115382$ (CI $[+0.111724,+0.119065]$). This is an aggregate ranking-value interaction rather than pervasive event-level sign reversal: 46,462 requests have zero Full--Long difference under at least one regime, and only 66 exhibit strictly opposite nonzero source-gap signs. A nine-cell decomposition attributes $+0.100885$ of the $+0.115382$ net interaction (87.4\%) to events with a zero source gap in at least one regime, consistent with a substantial sampled top-ten support effect. This motivates examining relation identity under a \emph{fixed} candidate environment rather than interpreting the source interaction as independent causal evidence.

On 1,024 stratified M3 DEV requests, valid historical-author nulls retaining source-hour author activity and user interaction times remain useful rankers but score below the original Full Memory under identical full-active author candidates (Supplementary S10.14). Across three prespecified null seeds, original-minus-null NDCG@10 lies between $+0.032858$ and $+0.035544$, with positive paired user-cluster intervals. The source swaps modify approximately 78.6\% of eligible history edges and also alter repeated-pair and higher-order relational structure; the contrast measures sensitivity to a strong time- and degree-preserving identity perturbation, not a uniquely identified causal effect of one relational feature. None of these development results is an additional independent TEST (Supplementary S10).

\subsection{Invocation Constraints and Measured Scoring Cost}
\label{sec:results-efficiency}

The M3 Utility rules realize $27.72$--$29.21\%$ Memory calls on TEST after the DEV call-limit calibration. History reaches $35.47\%$ on TEST, illustrating that a frozen pointwise rule need not preserve its DEV call fraction. Invocation rates alone do not measure full-path computation.

In a matched, exploratory nested M3 DEV sensitivity analysis, raising the inner specialist-call limit from $30\%$ to $50\%$ increases SASRec policy NDCG@10 from $0.302658$ to $0.319654$ and GRU4Rec from $0.303093$ to $0.320478$; at a $90\%$ limit both approach $0.34105$. Without any cap, the learned policies invoke Memory on $99.91\%$ (SASRec) and $99.44\%$ (GRU4Rec) of events, giving NDCG@10 $0.343495$ and $0.343363$, marginally below Always Memory $0.343509$. All limits are calibrated on inner DEV and actual outer rates may differ. An accompanying matched DEV comparison finds Direct relative-utility and separate two-stage utility prediction close, whereas predicting Base difficulty or Memory quality alone gives lower NDCG over $10\%$, $30\%$ and $50\%$ inner limits. These exploratory comparisons strengthen the interpretation of \emph{which decision target} is informative; they do not establish a new routing algorithm or measured saving in production resources (Supplementary S10). An additional decision-value analysis evaluates $J_{\lambda}(\pi)=V_F(\pi)-\lambda q(\pi)$, where $q$ is the \emph{actual outer} Memory-call fraction and $\lambda$ is a hypothetical disutility measured in expected event NDCG per specialist invocation. Among the recorded invocation-budget policies and fixed Base/Memory endpoints, the 30\%-inner-cap policy maximizes this idealized objective only for $\lambda\in[0.084516,0.111321]$ with SASRec and $\lambda\in[0.083119,0.104379]$ with GRU4Rec; at $\lambda=0$, Always Memory remains preferable. These point-estimate ranges assume zero incremental gate overhead and should not be interpreted as observed monetary or latency costs.

A first warmed RTX 3090 DEV replay on 256 M3 requests found a faster unconditional Memory scorer (mean $0.803$\,ms) than the Utility path ($1.802$\,ms), even at only 31.25\% Memory calls; the room-ranking CPU experiment reports a similar qualitative limitation under a different workload (Supplementary S9--S10). These distinct timing protocols are not directly comparable.



A second, counterbalanced DEV measurement repeats the same 256 full-active requests three times, using synchronized Base, Memory and the original frozen Utility gate branches (Table~\ref{tab:results-n10-cost}). It confirms that the gate's Base, feature and prediction overhead exceeds the avoided specialist-scoring work in this measured implementation. Full source-history reconstruction and availability-roster sweeps were timed separately rather than assigned to per-request online latency (Supplementary S10.17).

\section{Discussion}
\label{sec:discussion}

\subsection{The Relative Value of Relationship Knowledge}
\label{sec:discussion-operational-value}

The central object of this study is the incremental utility of an explicitly specified relationship-history ranker over an existing recommendation model, rather than the standalone strength or learned representation of that history. On Twitch, the same Memory specialist that underperforms Base overall improves ranking markedly for target creators present only in older observed relationships; on M3, Memory is stronger than six separately fitted incumbents in aggregate. These results establish heterogeneity and incumbent dependence across distinct tasks, not a causal attribution of their contrast to any one dataset characteristic. Because the value target is a difference between complete rankings over a specified candidate universe, it provides an operational test of whether using external knowledge changes a decision.

This contribution complements prior work on scene-conditioned memory admission, graph-knowledge fusion and dynamic model routing \cite{zhong2026samd,xie2026mhgfcl,yuan2026dsframe}. The novel empirical question here is whether the value of a \emph{fixed} historical evidence source, defined relative to its incumbent, remains informative when the ranking alternatives and the choice to use that source are themselves evaluated. Neither conditional memory selection nor general learning-to-defer is new in isolation.

\subsection{Candidate Context Defines the Value Being Predicted}
\label{sec:discussion-candidate-regimes}

A relative-ranking utility label is not intrinsic to the knowledge source: it also reflects which eligible alternatives compete at the decision. The paired original KuaiLive experiment reverses the aggregate sign of Memory--Base utility between sampled and full-active room candidates while holding target events and raw expert scoring functions fixed. Its crossed analysis associates nearly the entire aggregate change with candidate membership, a compound change in count, identity and competition rather than a count-only effect. This is consistent with known sampled-metric distortions \cite{krichene2020kdd}, but the subsequent M3 comparison tests a different consequence: labels trained under the full-active regime guide full-active knowledge-use decisions more effectively than retrospective sampled-candidate labels. Matched DEV policies redistribute calls across approximately 21--23\% of requests. On separately frozen additional targets, full-aligned policy advantages persist for both SASRec and GRU4Rec, although natural call totals differ and sampled DEV labels retain the observed target.

The historical-source controls distinguish that supervision effect from an exclusively candidate-driven explanation. With the same full-active candidates and Memory scorer, the authentic viewer--creator history outperforms three time- and activity-constrained author-label permutations in both development diagnostics and the additionally frozen targets. The intervention preserves the specified temporal and activity margins but disrupts repeated pairs and higher-order structure; it demonstrates the ranking value of the original \emph{history arrangement}, not the isolated effect of one relation attribute. On the 1,024-event development cohort the nulls also exceed the corresponding TRAIN-only Popularity reference. For the separate 4,096-target evaluation, however, the prespecified same-cohort Popularity margin was not sealed before label revelation; its full original nondegeneracy criterion therefore remains unverified (Supplementary S10.16 and S10.18).

\subsection{Predicted Marginal Value as a Selection Signal}
\label{sec:discussion-selective-decisions}

Conditional relative utility links evidence valuation to a testable choice: use Memory where pre-outcome descriptors predict that its complete ranking is better than the incumbent's. Frozen Twitch and M3 comparisons support this decision target relative to the specified Base-difficulty, specialist-quality and heuristic objectives under development-calibrated invocation constraints. In the original M3 evaluation the effect is consistent across two Base families and three fitting seeds; these fits share a TEST cohort and do not supply independent population replications. The gap to a hindsight Oracle leaves considerable prediction error, and unequal realized call rates mean these are comparisons of \emph{frozen operational policies}, not universal equal-budget optimality.

The decision target should not be confused with a new estimation principle. Directly estimating $\mathbb{E}[u_{10}(M)-u_{10}(B)\mid Z]$ and subtracting separately estimated conditional utilities have the same population target; their finite-sample accuracy and inference costs can differ. The DEV comparisons of direct and two-stage estimation are consequently implementation sensitivity checks (Supplementary S7 and S10). The distinctive insight is the joint specification of the fixed knowledge source, the actual candidate-regime utility label and the downstream invocation decision, rather than a claim to supersede established expert-delegation algorithms.

\subsection{Invocation Allocation and System Cost Are Distinct}
\label{sec:discussion-validity}

Choosing fewer Memory invocations is not the same as reducing latency or total computation. On M3, Always Memory is more accurate in absolute NDCG@10 than every tested selective policy. It is also faster than the original Utility selector in both warmed DEV scoring measurements, including the counterbalanced comparison of 256 distinct requests repeated three times (mean 0.692\,ms for Memory versus 1.769\,ms for the selector; Table~\ref{tab:results-n10-cost}). Computing Base, decision-time features and the gate creates overhead even when Memory is skipped. The measured result concerns the original pointwise Utility implementation, not production concurrency or the newer vectorized full-aligned gate; the separate full-source history and roster preparation times are not per-request serving latencies.

Thus the positive selection finding is a \emph{conditional allocation} result. A policy that sacrifices some unconditional ranking accuracy can be justified when Memory access faces a real external quota, cost, permission or capacity constraint. The DEV shadow-price analysis quantifies hypothetical tradeoffs in NDCG per additional specialist invocation, not dollars or milliseconds; without measured scarcity, unconditional Memory remains a compelling reference. Claims of deployment savings require a workload-matched serving study and evidence that a nontrivial invocation constraint actually applies.

\subsection{Transferability and Implications for Knowledge-Based Recommendation}
\label{sec:discussion-implications}

The experiments provide complementary, not interchangeable, evidence. Twitch evaluates streamers; original KuaiLive evaluates rooms in a retrospective paired candidate experiment; M3 evaluates persistent authors in a forward-time protocol. The added 30,000 ranking targets, including the nested 4,096 history-perturbation targets, are excluded from the original evaluated M3 target IDs but come from the \emph{same recording period} and may share users and earlier observations. The five date-specific findings are descriptive groups, not five forward-time external replications. Outcome-defined history states, retrospective sampled-label comparisons and strong historical permutations are mechanistic diagnostics rather than information available to a deployed selector.

For knowledge-enhanced recommendation, the resulting evaluation discipline is to define the \emph{incumbent and candidate set}, identify the \emph{unchanged external knowledge source}, estimate its \emph{marginal downstream value} using pre-outcome features, evaluate \emph{actual selection consequences}, and test source specificity with a fixed candidate universe. This connects knowledge representation to observable decision value while keeping causal mechanism, independent temporal transfer and net operating costs as separate empirical questions.

\section{Conclusion}
\label{sec:conclusion}

A fixed relationship-memory ranker has no context-free incremental value: its contribution depends on the trained incumbent and on the candidates eligible at decision time. Across streamer-, room- and author-ranking protocols, we observed heterogeneous historical complementarity and a paired reversal of Memory--Base ranking value under different candidate regimes. In full-active M3 author ranking, candidate-aligned utility supervision improved the subsequent frozen selection decisions of SASRec and GRU4Rec on 30,000 additional same-period targets, and authentic historical relationships outperformed time- and activity-constrained alternatives on a nested 4,096-target set with identical candidates. These results jointly support incumbent-relative knowledge valuation, candidate-aligned decisions and source-specific historical evidence, subject to the stated sampling and control limitations.

The research contribution is a reproducible framework for \emph{evaluating when explicitly identified knowledge improves a particular ranking decision}, not a new generic routing algorithm. Pre-outcome relative-value estimates help allocate specialist calls under stipulated invocation constraints, but unconditional Memory remains more accurate and faster in the measured M3 configuration. Deployment savings, isolation of individual relation mechanisms and future-period transfer require separate evidence. The broader implication is that the value of auxiliary knowledge should be assessed through the decisions it changes, with both candidate context and actual access constraints made explicit.
