## Central claim and inferential ladder

> A persistent user–creator history is useful to a knowledge-based recommender when an existing specialist turns it into **positive incremental ranking utility relative to the particular Base and candidate environment**; observable context can predict a limited part of that conditional value before an outcome is known.

**A. Measure value (C1, 6.1):** Define per-event `Δ_M=u(M)−u(B)`; the Twitch TEST full average is negative while recoverable-history cases are positive. This supports *heterogeneity*, not a deployable target-aware routing signal.

**B. Make a decision (C3, 6.2):** Define pre-outcome conditional `η_r`, compare one DEV-frozen rule to Base and same-call Difficulty. Frozen TEST Utility − Base = **+0.00772**; selected/unselected conditional means are arithmetic restatements, not new inference.

**C. Diagnose the environment (C2, 6.3):** A fixed KuaiLive checkpoint and 10,222 matched events produce a sampled −0.04120 versus full +0.04631 relative-utility reversal. The 2×2 score-reference analysis, P1 model seeds and P2 candidate draws are protocol-bound post-hoc tests, not new Twitch policy confirmations.

**D. Discriminate mechanisms and costs (6.4/6.5):** DEV OOF features, local Memory perturbation, component variants and independent Base contexts explain relevant conditions, not causal components or broad benchmark supremacy. The warm KuaiLive CPU benchmark finds 2.03× Base latency, a substantive negative resource finding.
