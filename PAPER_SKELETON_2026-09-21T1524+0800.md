# 1. Recommended title

## Primary

> **Learning When Memory Helps: Conditional Specialist Utility for Live-Streaming Recommendation**

## Alternative

> **When Does Memory Help? Conditional Utility of Explicit Relationship Memory in Live-Streaming Recommendation**

Do not center the title on generic adaptive computation, fast/slow thinking, uncertainty-aware recommendation, agentic recommendation, or memory-augmented recommendation. Those spaces now have direct 2025–2026 collisions.

# 2. Core thesis and novelty boundary

> **Explicit relationship memory is not a uniformly stronger recommender. In next-live-room recommendation it can be worse than a strong identity-aware sequential base on average yet predictably useful on subsets, and the prevalence of this positive relative utility changes sharply across temporal regimes.**

The paper is **not** claiming invention of generic expert routing or deferral. Learning-to-Defer (L2D) already studies instance-wise assignment between predictors/experts, including two-stage fixed-expert settings and accuracy–cost trade-offs (e.g., Mao, Mohri & Zhong, ICML 2025: https://proceedings.mlr.press/v267/mao25c.html). The defensible novelty is the empirical and methodological combination specific to live recommendation:

1. an **explicit relationship-memory specialist** separate from a strong sequential base;
2. the specialist is **globally inferior but locally complementary** in the ordinary LOO regime;
3. the complementarity survives **persistent streamer-identity absorption** by a Dual-ID base;
4. the target of the selector is **specialist-minus-base ranking utility**, not merely base difficulty;
5. the distribution of relative memory utility is **regime-dependent** under strict temporal shift;
6. selective-inference cost depends jointly on **selector complexity and specialist invocation**.

Safe claim:

> Rather than assuming that an auxiliary memory model is globally stronger, we study a harder live-recommendation regime in which explicit relationship memory is inferior on average yet beneficial on identifiable subsets, and we characterize how that relative value changes with identity information and temporal regime.

Avoid “first” claims.

# 3. Primary task and problem formulation

The main paper uses **next-live-room recommendation** as the primary task. Streamer-level results are supporting/development evidence rather than the manuscript's main task.

Let `B` be the final strong room+streamer **Dual-ID sequential base** and `M` the explicit relationship-memory specialist. Let `u_K(A,x)` denote event-level ranking utility (primarily NDCG@10) of system `A` for interaction state `x`.

Define realized relative memory utility:

\[
\Delta_m(x)=u_K(M,x)-u_K(B,x).
\]

The statistically safer population object is conditional expected relative utility:

\[
\eta(z)=\mathbb E[\Delta_m(X)\mid Z=z],
\]

where `z=(s_x,c_B(x))` combines user/interaction state and base-confidence features. Fit a dev-only estimator

\[
\hat\eta(z)=g(z),
\]

and escalate to memory when

\[
\hat\eta(z)>\tau,
\]

with all model/threshold choices made on development data only.

Preferred terminology:

- conditional relative utility;
- marginal predictive utility;
- relationship-memory specialist;
- memory escalation;
- identity-aware sequential base.

Avoid causal treatment-effect language. `utility` here is **offline ranking utility**, not GMV, conversion, satisfaction, or causal business value.

# 4. Research questions

## RQ1 — Is explicit relationship memory uniformly superior to a strong live-room recommender?

No. In the ordinary LOO regime, Always Memory is globally inferior to the strong sequential base, while memory still has positive realized utility on subsets.

## RQ2 — Is memory-relative utility predictable beyond persistent identity and generic base difficulty?

Test with:

- Dual-ID identity control;
- predicted-utility deciles vs realized `Memory − Base` utility;
- matched-budget **relative-utility router vs base-difficulty router**;
- Dual-ID history/state/confidence information ablations;
- oracle headroom.

## RQ3 — Does the distribution of positive memory utility change across temporal regimes?

Yes. GTS-Last and GTS-Successive show that memory becomes broadly useful under temporal shift and invocation rises from roughly 14% to 60–75%.

## RQ4 — What are the accuracy–invocation–latency trade-offs of selective memory?

Gate-compression experiments show that selector cost can dominate incremental latency; invocation rate alone is not a valid compute proxy.

# 5. Four manuscript contributions

## C1 — Empirical phenomenon: globally inferior yet locally complementary relationship memory

Primary Dual-ID room evidence:

- Room SASRec: 0.3150925
- Streamer SASRec: 0.6003083
- Dual-ID: **0.6078439**
- Always MemoryFusion: **0.5658875**
- Frozen Selective Dual+Memory: **0.6210175**
- Selective − Dual-ID: **+0.0131736**
- 95% CI strictly positive
- memory invocation: **14.2536%**
- dev fusion: room 0.1 / streamer 0.9.

Canonical claim:

> **Even after persistent streamer identity is absorbed into a strong Dual-ID sequential recommender, explicit relationship memory remains globally inferior yet conditionally complementary.**

Earlier streamer-level SASRec-v2 evidence is supporting/appendix robustness, not the lead result.

## C2 — Relative-utility estimation beyond generic difficulty

The scientific target is `Memory − Base`, not merely “hardness.” Main evidence should include:

- predicted relative-utility deciles vs realized relative utility;
- matched-budget relative-utility HGB vs a base-difficulty HGB trained on the same features;
- history threshold / state only / confidence only / state+confidence under the final Dual-ID base;
- oracle exact-budget and unrestricted headroom.

The method contribution should be written narrowly: applying dev-only relative-utility estimation to determine when a **relationship-memory specialist** adds ranking value beyond a strong live-room base. Do not present generic deferral/routing as new.

## C3 — Identity robustness and temporal regime dependence

Strict temporal evidence:

### GTS-Last

- Dual-ID: 0.4961552
- Always Memory: 0.5736936
- Selective: 0.5689723
- invocation: 59.80%
- selective retains ~93.9% of full-memory absolute improvement.

### GTS-Successive

- Dual-ID event NDCG@10: 0.4030069
- Always Memory: 0.5036781
- Selective: 0.5004335
- invocation: 74.73%
- selective retains ~96.8% of full-memory gain.

Canonical claim:

> **The prevalence of positive relationship-memory utility is regime-dependent: memory is a minority specialist in ordinary LOO but becomes broadly valuable under strict temporal shift.**

Do not claim Selective always maximizes accuracy; Always Memory is slightly higher in both GTS variants.

## C4 — Deployment implication: selector complexity is part of selective-inference cost

Frozen gate-compression evidence:

| Gate | NDCG@10 | Delta vs Dual-ID | Invocation | Mean end-to-end latency |
|---|---:|---:|---:|---:|
| HGB | 0.621018 | +0.013174 | 14.25% | 2.0066 ms |
| Ridge | **0.623876** | **+0.016032** | 30.99% | **1.3872 ms** |
| tiny MLP | 0.617076 | +0.009232 | **10.37%** | **1.2720 ms** |

Selector-only means:

- HGB ~0.617 ms
- Ridge ~0.00242 ms
- tiny MLP ~0.00575 ms.

Canonical claim:

> **End-to-end selective cost depends jointly on selector complexity and specialist invocation; a lighter selector can invoke memory more often yet remain faster overall.**

HGB remains the primary scientific selector because the frozen robustness/GTS chain is built around it. Ridge is a deployment variant.

# 6. Narrative logic

## Act 1 — Live-room recommendation contains ephemeral items but persistent relationships

Rooms are ephemeral while streamer relationships persist. A room-only model is therefore weak, but simply exploiting streamer identity can create an apparent memory advantage.

## Act 2 — Build the strongest identity-aware base first

The final primary base is Dual-ID room+streamer SASRec. The optimal dev fusion is streamer-heavy, explicitly absorbing persistent identity.

## Act 3 — The paradox

Despite this, Always Memory is globally worse than Dual-ID, yet frozen Selective Memory significantly improves it. Average model ranking therefore hides heterogeneous relative utility.

## Act 4 — Show that the selector learns relative specialist value, not only hard cases

Use utility calibration, utility-vs-difficulty matched-budget routing, information-source ablations, and oracle headroom.

## Act 5 — Show that relative utility is not stationary

Under strict temporal splits, memory changes from minority specialist to broadly useful expert. The scientific object is the **distribution of relative utility**, not a fixed global model ranking.

## Act 6 — Separate this from generic adaptive computation / deferral

DS-Frame is an important recommendation-specific collision: its slow path is globally stronger than its fast path. L2D is the broader generic routing lineage. Our novelty is not generic routing but the live-recommendation memory regime and its identity/temporal behavior.

## Act 7 — Close with deployment cost

Selector complexity can dominate the incremental serving cost; invocation frequency is insufficient as a systems metric.

# 8. Experimental setup hierarchy

## Primary dataset/task

KuaiLive Shop subset; next `live_id`; legal active-at-target-time candidates.

## Primary ordinary-regime base

Dual-ID = room-SASRec + streamer-SASRec fusion chosen on dev only.

## Primary specialist

Frozen MemoryFusion relationship-memory score projected from persistent streamer history to currently active rooms.

## Primary selector

Frozen HGB relative-utility estimator trained/thresholded on dev only.

## Candidate protocols

1. frozen sampled-active protocol: target + 574 legal active negatives;
2. **full-active candidate robustness**, reported in two pre-specified modes:
   - **strict-transfer stress test:** sampled-regime alpha/gate/threshold transferred unchanged where computationally definable;
   - **full-active-native evaluation:** alpha/confidence features/gate/threshold recalibrated on full-active **dev only**, followed by one-shot test evaluation.

This split is necessary because candidate-set expansion changes score normalization and confidence-feature distributions.

## Significance

Paired user-cluster bootstrap, at least 5,000 resamples for final main comparisons.

# 10. Claims that are safe vs unsafe

## Safe

- explicit relationship memory is globally inferior but conditionally complementary in ordinary LOO;
- the complementarity survives a strong streamer-heavy Dual-ID identity control;
- predicted relative utility tracks realized specialist advantage if P0-B passes;
- relative-utility routing beats generic difficulty routing if the matched-budget test passes;
- positive memory utility is regime-dependent;
- selector cost and specialist invocation jointly determine latency.

## Unsafe

- “first conditional routing recommender”;
- “first learning-to-defer recommender”;
- “agent beats SASRec”;
- “MemoryFusion is an LLM agent”;
- “Selective always beats Always Memory”;
- “Selective beats DS-Frame routing”;
- causal GMV/conversion claims;
- claiming full-active validity before P0-A is complete.
